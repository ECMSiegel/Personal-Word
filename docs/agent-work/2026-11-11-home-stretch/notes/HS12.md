# HS12 Toolbar buttons return focus to the editor at once

Cause: Tiptap's `.focus()` calls `view.focus()` one animation frame later, so a key typed right after a click lands on the
toolbar button. Font size +/- never focused the editor at all.

## Changed (src/Writer.tsx only)
- Shared `iconButton` onClick (Bold, Italic, Underline, Strike, bullet/numbered list, quote): `t.run(); editor.view.focus();` -- one place.
- Undo, Redo, Decrease/Increase font size, Decrease/Increase indent, Remove link: `editor.view.focus()` after the command.
- Tests: tests/hs11-font-focus.spec.ts (+8 cases). Fail-first: notes/HS12-fail-first.txt (7 failed: button kept focus; size + lost "Big").

## Audit
- Already fine: Font family, Paragraph style, Screenplay style (HS11), Insert table (focus now).
- Fixed: shared icon buttons, Undo, Redo, font size +/-, indent +/-, Remove link.
- Deliberately left: Table controls popover buttons (popover stays open for repeated edits; they still use Tiptap focus()),
  line-spacing presets and its number boxes, font-size NumberInput, Zoom/Paper/Margins/Position dropdowns (not editing
  commands or popover stays open), Add link (opens the link dialog which needs focus), Page view/Focus mode toggles.
  No alignment or colour control exists in the toolbar.

## Limits
Chromium only; native WebKit timing unchecked. The click test uses el.focus()+el.click() (a real click focuses the button
first) and reads activeElement in the same task.

## Hand check
Select text or place the caret, click Bold / the list button / A+ and type at once: letters appear in the text, nothing is lost.
Tab to Bold, press Space: bold toggles and no space is typed.

## Rework (after REVIEW-6)
Immediate `editor.view.focus()` is now pointer-only: `onClick={(e) => ... if (e.detail > 0) editor.view.focus()}`
(keyboard activation has detail 0). Applied to shared iconButton, Undo, Redo, size -/+, indent -/+, Remove link, and
newly Delete table and Insert page break. Keyboard before HS12 == now:
- Bold/Italic/Underline/Strike/lists/Quote, Undo, Redo, Remove link, Delete table: Tiptap `.focus()` (editor focused one frame later) -- unchanged.
- Indent -/+: `changeIndent` chain `.focus()` (one frame later) -- unchanged.
- Font size -/+: no focus move; focus stays on the button so Space can repeat -- unchanged.
- Insert page break: `editor.commands.focus()` (one frame later) -- unchanged.
Bullet list + Enter (finding 3): the 1 -> 2 top-level blocks was NOT focus-related. The editor keeps an empty trailing
paragraph after a list (a pointer click on Bullet list gives UL + P too), so it is pre-existing and not fixed. The test now
checks one `ul > li` (the item is not split). That case passed on the pre-fix code too, so it is a guard, not fail-first.
Tests: pointer cases use a detail-1 click; added Space x3 on size +/-, Enter on Bullet list, Delete table and Insert page
break pointer cases; Undo case asserts the typing was undone; selection case asserts the size changed.
Fail-first: notes/HS12-rework-fail-first.txt (5 failed; 4 real: Space x3 +/-, Delete table, Insert page break; the Enter case failed only on the trailing-paragraph count and was corrected).
