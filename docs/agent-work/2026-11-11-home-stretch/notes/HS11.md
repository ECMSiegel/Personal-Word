# HS11 Four failures from the full built-app e2e run

## 4. w9-fonts:72 -- "Trebuchet specimen" typed as "ebuchet specimen" (APP BUG, fixed)
Root cause (evidence): a temporary diagnostic logged every keydown/focus change in the built app
(preview), 8 repeats. In the runs that lost text, the lost `T` keydown targeted
`button.dropdown-button[Font family]` (6 of 8 runs); in the good runs it targeted the editor.
Sequence on choosing an option: `Dropdown.choose()` focuses the dropdown button, then the toolbar's
`onChange` runs `editor.chain().focus()...`. Tiptap 3's focus command calls `view.focus()` inside
`requestAnimationFrame` (only Safari-UA browsers get a synchronous focus; Chromium and, by its user
agent, likely the Tauri WKWebView do not). Keys that arrive before that frame land on the button
and are dropped. The same one-frame gap was already fixed for "Insert table" (Writer.tsx comment
"Tiptap's focus() defers view.focus() one frame").
Which batch change exposed it: not isolated. There is no git history to bisect; the gap is older
than this batch and the failure is timing-dependent (built app is faster to hit it than dev).
Fix: `editor.view.focus()` straight after the chain in the three toolbar dropdowns that hand focus to
the editor -- src/Writer.tsx Paragraph style onChange (~1326-1337), Screenplay paragraph style
(~1348-1356), Font family (~1395-1400). Smallest change; same pattern as Insert table.
Pin: tests/hs11-font-focus.spec.ts clicks the option and reads `document.activeElement` in the same
task (deterministic, no typing race). Fail-first: notes/HS11-fail-first.txt (both cases received the
dropdown button, not "Writing editor"). After: passes.

## 1. hs1-export-menu:5 -- "Export settings..." not topmost (TEST PROBLEM, fixed in the test)
Root cause: the Popover opens with a clip-path reveal (`inset(0 0 100% 0)` -> `inset(0)`) and its rows
drop in. Hit-testing straight after `toBeVisible()` ran mid-reveal: at 0 ms every row's centre hit
`div.editor-paper` / `.editor-viewport` (still clipped); at 400 ms every row hit itself, with
`z-index: 41` applied in the built CSS. The dev server was slow enough to finish the reveal first.
The menu is not hidden for the owner once open. Fix: the test waits for the menu's animations
(`getAnimations({subtree:true})` finished) before checking. Teeth: with `.export-menu.popover
{z-index:40}` injected, the settled check still fails on "Word (.docx)" (8/8).
