# A2 -- Sidebar scrollbar and sideways scroll (T256)

## What changed
- `src/styles.css` `.sidebar-groups`: `overflow-x: hidden`, `overflow-y: auto`, `scrollbar-width: none`, and `::-webkit-scrollbar { display: none }`. The group list still scrolls vertically; its scrollbar is hidden and it cannot scroll sideways.
- `src/components/ProjectSidebar.tsx`: the E2 scroll-fade hook now runs in docked mode as well as floating (the `isFloating &&` condition is gone; dependency stays `[isFloating]`). The edge fade is the scroll cue in both modes.
- New spec `tests/w9-sidebar-scroll.spec.ts`: at 1100 x 500 with 25 added sections, asserts the computed overflow values, scrollbar-width none, zero scrollbar gutter, and that the wheel scrolls the list.

## What a user sees
- On a short window, the sidebar's project list has no visible scrollbar. It still scrolls with the wheel or trackpad.
- The list no longer drags sideways.
- The edge fade now also shows in the normal docked sidebar when there are more rows above or below.

## Limitations
- Scrolling without a bar is discoverable only through the fade and by trying the wheel; there is no keyboard-visible scrollbar.
- The gutter check is from headless Chromium. Native WebKit was not checked.

## Evidence
- Fail-first: `notes/A2-fail-first.txt`. Before the fix the spec failed at the first style assertion: `overflow-x` was `auto`, expected `hidden`.
- Acceptance: `tests/w9-sidebar-scroll.spec.ts`, `tests/scroll-fade.spec.ts`, `tests/floating.spec.ts` on port 1432 under the serial lock: 43 passed, 0 failed (log: node_modules/.cache/personal-word-beta/T256-accept.log).

## Hand check
1. Open the project at about 1100 x 500 with the sidebar pinned and about 25 sections in Manuscript.
2. Confirm there is no scrollbar on the sidebar list and the list scrolls with the wheel.
3. Try dragging the list sideways: it should not move.
4. Confirm the top or bottom edge shows the fade when rows continue beyond it.
