# E1 (board task T271) -- Export menu in the header

Agent agent-5772, 2026-11-10. Status: CLAIMED (Chromium dev server only; no native run).

## What changed
- `src/export/exportActions.ts` (new): `ExportFormat`, `exportProject(project, format)` ->
  `"saved" | "canceled"` (throws an Error with a readable message), plus `collectAndResolveAssets`
  and `exportFormatLabel`. The bodies of the old `save`, `saveText`, `saveMarkdownBundle` moved here
  with the same file names, MIME types and missing-image error. The param type is `ExportProject`
  (what `ExportPanel` already had), a supertype of `Project`.
- `src/export/ExportPanel.tsx`: one `save(format)` calls `exportProject`; it keeps its own busy and
  message state and all its buttons. "Preview PDF" now uses the shared `collectAndResolveAssets`.
- `src/export/ExportMenu.tsx` (new): text button "Export" (Download icon, same `.snapshot-button`
  look as Snapshot) opening a `Popover` role=menu named "Export": Word (.docx), PDF, Markdown,
  Markdown with images (.zip), Plain text, a rule, Export settings..., Complete project (.json).
  Arrow keys, Home, End, Enter, Escape (returns focus to the button), Tab closes. Opening by any
  route focuses the first item. Results show through the app's notice; failures through its error.
- `src/App.tsx`: the portable-project icon button is replaced by `<ExportMenu>`; `exportMenuOpen`
  state; `exportCompleteProject` holds the code that was behind the icon; `runAppAction` handles
  `exportDocument` by opening the menu; the palette lists it as "Export..." (the generic Actions
  mapping, label swapped for this one id, so it also shows the chord hint).
- `src/shortcuts/registry.ts`: `exportDocument`, label "Export", Cmd+Shift+E. It appears in
  Settings > Shortcuts and can be rebound.
- Tests: `src/export/exportActions.test.ts`, `tests/w9-export-menu.spec.ts`.

## What a user sees
The download icon in the header is now a text button "Export" beside Snapshot. Click it or press
Cmd+Shift+E (or choose "Export..." in the command palette).

## Plan versus code
1. Menu rows and the rule use `src/export/export-menu.css`, scoped to the export menu. Its
   `:focus-visible` outline offset matches the create menu without editing P1's `library.css`.
2. **Export settings... depends on S1 (T275), now approved.** `scrollToSettingsSection` is wired to
   S1's implementation. The full six-case E1 browser spec must be rerun and pass before review;
   the prior 5/6 run predates S1.
3. The unit tests cover "canceled", "saved", file names, and the readable missing-asset failure.
   Vitest 4 treats a rejected `vi.fn` save mock as its own test error, so the failure-path test uses
   the plain async storage mock at the asset-loading boundary instead.
4. No existing spec clicks "Export portable project" (searched `tests/`), Cmd+Shift+E is not used
   by any native menu accelerator (searched `src-tauri/src`), and the header does not overlap at
   1100 px with a 60-character title, so none of the stop conditions applied. Not checked: whether
   macOS/WebKit itself swallows Cmd+Shift+E (needs the built app).

5. The Export button first carried `.snapshot-button`; that collided with three strict-mode
   selectors in `tests/hover-emphasis.spec.ts` (reported by T255's owner). It now has no such class;
   its sizing is in `export-menu.css`, so only the real Snapshot button matches. The text hover rule
   still applies (it is a plain button).
