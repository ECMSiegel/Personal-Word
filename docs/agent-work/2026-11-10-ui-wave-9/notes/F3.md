# F3 -- Saved interface font applies at once (T281, REVIEW.md B-S1)

## What changed
- `src/fonts/registry.ts` `initFonts`: sets `--ui-font` to the saved font before any await. It resets the saved choice to Futura only when the installed-font list actually loaded (non-empty) and the font is in no list. A failed or empty installed list never overwrites the saved choice.
- `src/fonts/registry.test.ts`: 4 new tests (saved font applied before the lists resolve; kept when the installed list rejects; kept when it is empty; still reset when the list loaded and the font is truly absent).
- Fail-first: `notes/F3-fail-first.txt` (3 of the new tests failed before the fix).

## What a user sees
The interface font they picked is in place from the first paint, with no Futura flash. One failed native font call no longer loses an installed-font choice.

## Limitations
- Outside the native app the installed list is always empty, so a saved font that no longer exists is not reset there (only the native app can tell). A truly missing font just falls back through its CSS stack.
- If the user list is the only one that loaded and the saved font is absent, the font is kept rather than reset (empty installed list counts as unknown).

## Hand check (native app)
1. Settings, pick an installed font (e.g. Menlo) as the interface font.
2. Quit Personal Word fully and relaunch.
3. Expect: the same font is still selected in Settings, and the window never shows Futura first.
