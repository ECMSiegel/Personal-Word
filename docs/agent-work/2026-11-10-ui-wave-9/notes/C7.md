## What changed
- `src/export/docx.ts`: `exportDocx(project, assets?, fontSource = defaultFontSource())`. New helper
  `embeddedFonts` collects the distinct (family, bold, italic) triples of runs with a font value (body
  blocks, table cells at any depth, and footnote parts), resolves each once through the source, keeps
  results whose `embedding` is `installable` or `editable`, one entry per family (the regular face when
  several resolved), and passes them as the document's `fonts` option (`data` = raw bytes cast to
  `Buffer`; the docx library accepted a `Uint8Array`). Any rejection or null just means "not embedded".
  Run font names are written exactly as before (same expression, now the shared `runFont` helper only
  for the collection step; the two `TextRun` sites are untouched).
- `src/export/docx-fonts.test.ts`: 6 tests (embed installable; embed editable; preview and restricted
  not embedded but named; null source; rejecting source; one lookup per triple and one entry per family).

## Repair after review (opencode-watch, 2026-11-11)

Reviewer finding 1 (blocking), the plan's unanswered stop rule defaulted to
"embed TrueType only":

- `src/export/docx.ts`: new `isTrueType` check -- only bytes whose first four
  bytes are `00 01 00 00` or the ASCII tag `true` are embedded. `OTTO` (CFF)
  and anything else is skipped, and the family's run names are still written
  as before. Recorded for `docs/limitations.md` (D1): **embedded fonts:
  TrueType only** (no WOFF, no CFF/OTTO).
- Pack guard: `Packer.toBlob` is now called in a `try`; if it throws while
  fonts are set, the document is rebuilt once without the `fonts` option so
  the export still succeeds exactly as today's no-font export. A throw with
  no fonts set is rethrown (unchanged behaviour).
- New tests, both shown failing before the guard (2 failed | 6 passed on the
  untouched implementation):
  - "does not embed an OTTO (CFF) font and the export still succeeds" -- a
    resolved installable font whose bytes start with `OTTO` is not embedded
    and the export resolves with the run name kept.
  - "falls back to a no-fonts export when packing a bad font throws" -- the
    docx module is stubbed with a `Packer.toBlob` that throws only for a
    poisoned family ("Poison Face"), proving the fallback rebuild.
- Fixture change forced by the rule: the old tests used the bundled Noto Sans
  **WOFF** (`noto-sans-latin-400-normal.woff`, magic `wOFF`) as their bytes.
  WOFF is not TrueType, so under the new rule it is not embedded; the fixtures
  now use synthetic TrueType bytes (four-byte `00 01 00 00` magic -- the packer
  stores bytes as given). No expectation changed: the old six tests assert the
  same outcomes as before, on TrueType bytes.

## What a user sees
A `.docx` exported from a project that uses an added font (or an installed one the app can read) carries
that font inside the file when its licence flags allow it, so Word may display it on a Mac without the font.

## Plan versus code
- `FontOptions.data` is typed `Buffer`; `Uint8Array` works at runtime in vitest (Node).
  Not tried in the browser/WebKit build (no `Buffer` global there is expected; docx did not need one
  in this test, but that is Node). The finding-1 pack guard makes a browser-side failure harmless.
  Check once in the app (T278).
- Embedded fonts: TrueType only. CFF/OTTO, WOFF and any other outline format is skipped by the
  `isTrueType` check, and a `Packer` throw while fonts are set falls back to a no-fonts export.
- Tests inject the source; the default source is used only when a run carries a font, and its failures
  are swallowed by the `try` in `embeddedFonts`.
