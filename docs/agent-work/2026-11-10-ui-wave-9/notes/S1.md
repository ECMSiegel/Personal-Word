# S1 (board task T275) -- Settings section strip

Agent agent-e113, 2026-11-10. Nothing committed. Status: CLAIMED (Chromium dev server only).

## What changed
- `src/settings/SettingsNav.tsx`: real `<SettingsNav />` and `scrollToSettingsSection(heading)`.
  Finds its `.project-settings` ancestor, reads the direct-child `.settings-section` elements that
  have an `h2`, gives each an id (`settings-<slug>`, unique) if it has none, renders one `<a>` per
  section. A `MutationObserver` on the container's direct children re-reads the list. An
  `IntersectionObserver` (root = the Settings scroller, band = upper third under the strip) sets
  `aria-current="true"` on the link of the section in view; a click also sets it at once.
  Click: pointer = smooth scroll; keyboard-triggered click (`event.detail === 0`) or Reduce Motion =
  instant. The heading lands 8 px under the strip. `scrollToSettingsSection` scrolls instantly; if the
  section is not mounted yet it waits (MutationObserver on `document.body`, 2 s cap).
- `src/settings/settings-nav.css`: sticky strip, `--paper` background, 1px bottom `--line`. Links are
  `--muted`, `--text` on hover/focus, and weight 600 + `--accent` when current; no fill, no hover rule
  of its own.
- `tests/w9-settings-nav.spec.ts`: 4 tests.

## What a user sees
A row of section names under "Project settings" that stays pinned at the top of the page while it
scrolls. Clicking one scrolls to that section; the one in view is bold and blue.

## Plan versus code
- The Settings page IS its own scroll container (`div.project-settings`, `overflow: auto`,
  `research.css:411`), so no stop rule applied.
- That container has 40 px top padding and sticky rests at the content edge, so the strip uses
  `top: -40px` to sit flush at the page top. This hard-codes the padding from `research.css`
  (not mine); if that padding changes, change `top`.
- Only the Project settings page gets the strip; the Library settings dialog does not render
  `<SettingsNav />` (T0 only placed it in `App.tsx`).
- Sections counted are direct children `.settings-section` with an `h2`; the Shortcuts block is not
  a `.settings-section`, so it has no link (as the plan's selector says).
