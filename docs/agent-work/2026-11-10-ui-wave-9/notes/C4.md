# W9 C4 -- Fonts in PDF export

- **Changed:** PDF export now resolves each distinct applied body-font family/style once, embeds permitted font files as subsets, and uses them for measurement and drawing. Restricted, missing, unreadable, or unembeddable fonts keep the existing bundled-font fallback. Notes and bibliography remain on the existing bundled-font path. Added unit coverage for added-font style selection and system-font resolution.
- **Fail-first evidence:** The prior session reported that `npx vitest run src/export/pdf-fonts.test.ts` failed before integration because the applied custom font was not embedded and the resolver was not called; that earlier run is not independently verified here. During this session, the first fixture compared a custom-only paragraph with the bundled-only output, so the custom font replaced the regular font and the expected font-count increase was invalid. I changed the fixture to retain an unformatted run beside the custom-font run, keeping the text identical in the baseline; the corrected regression check passes.
- **Verification:** `npx tsc -b` passed. `npx vitest run src/export` passed all 167 tests across 9 files. The PDF regression test also passed in isolation (4/4).
- **Limitations:** Automated tests only; no native/WebKit run or Preview inspection was performed. PDF's existing Latin, Greek and Cyrillic shaping limits remain.
- **Hand check:** In Personal Word, export a PDF with one paragraph each in an added font, Georgia and Futura. Open it in Preview and choose Tools > Show Inspector > Fonts. Confirm Georgia is listed; Futura is a collection font and is expected to fall back. Confirm the added font appears when its embedding permission allows it.
