# G1 -- "Used in" locations and Go to (T272)

## What changed
- `src/derived/footnoteLocations.ts` (new): `footnoteLocations(project)` returns a map from footnote id to the entry that holds its marker (`entryId`, `title`). It walks each entry's content for `footnoteReference` nodes. The first entry in project order wins. Results are cached per project object, so the same object is returned for the same project.
- `src/derived/footnoteLocations.test.ts` (new): four unit tests (section, fragment, unreferenced footnote, memoised).
- `src/App.tsx` (small regions only):
  - import of `footnoteLocations`;
  - `pendingFootnote` ref, and a `selectFootnoteMarker(editor, id)` helper next to `showBibliography`;
  - a branch in `editorReady` that selects the pending marker once the target entry's editor mounts;
  - `goToFootnote(id)` placed before `const writing`. If the target section already has a live editor in a pane, it selects the marker there directly. Otherwise it opens the section the way a sidebar click does and selects the marker when the editor mounts;
  - the `ResearchPanel` call now passes `footnoteLocations={footnoteLocations(project)}` and `onGoToFootnote={goToFootnote}`.
- `tests/w9-used-in.spec.ts` (new): four browser tests. The fourth (rework r2) opens a source cited from section Two, from section One, and checks its "Used in" row reads "in Two" and that Go to selects the marker in Two.
- `src/research/ResearchPanel.tsx` is unchanged. Its props matched the plan.

## What a user sees
- In the Research panel, each footnote row whose marker sits in a manuscript section or fragment shows "in <title>" with a "Go to" button.
- Go to shows that section in the focused pane (or focuses the pane that already shows it, in a split). It selects the footnote marker and scrolls it into view. The Research panel stays open.
- Keyboard: Go to is a normal button, so Tab to it and press Enter.

## Limitations
- A footnote marker that appears in more than one entry reports only the first entry in project order.
- Not checked in native WebKit (the Tauri app). Chromium only.
- Go to relies on the editor for the target section mounting in the same tick as the selection call. The existing comment "Go to passage" jump uses the same pattern; the plan's stop-and-ask condition was not triggered.

## Hand check
1. Start the dev server or run the browser test.
2. Create a project with sections "One" and "Two". In "Two", type a sentence, then Research > "Insert footnote at cursor", and enter text.
3. Click section "One" in the sidebar. Open Research. The footnote row should read "in Two" with a "Go to" button.
4. Click "Go to". Section "Two" should open with the footnote marker selected and visible, and Research should stay open.
5. Repeat with Cmd+click to open "Two" beside "One". Click into "One", then click "Go to". The right pane should take focus and neither pane's section should change.
