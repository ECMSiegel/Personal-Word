# F4 -- Prose check popover height and the invisible context menu frame

## What changed
1. `tests/fixtures/popover-baseline-rects.json`: the "Prose check" height changed from 232 to 146. Nothing else in the file changed (git diff: one line). This is review item A1: the Prose check popover is shorter after B2, not broken.
2. `src/components/ContextMenu.tsx` line 145: `data-animate` is now left unset when the menu opens from the keyboard OR when the system asks for reduced motion. Before, a pointer-opened menu under Reduce Motion got `data-animate=""` and sat at opacity 0 for one frame before `data-shown` arrived. Review item A5. (git diff: one line.)

## What a user sees
- Pointer-opened sidebar context menus under Reduce Motion appear at once instead of being invisible for one frame. No change with Reduce Motion off.
- No visual change to the Prose check popover; only the test baseline moved.

## Fail-first
- Before edit 2, `sidebar-context-menu.spec.ts --repeat-each 10` gave 109 passed, 40 skipped, 1 failed (EXIT 1). Log: `notes/F4-fail-first.txt`.
- The failure was NOT the Reduce Motion race. It was "floating sidebar, short window > the scrolling group list ends above the bottom rows": the Save click was detached from the DOM and timed out after 90 s. The test passes in `notes/baseline-dev.txt`. It is a separate flake. Not fixed here.
- The race itself (the Reduce Motion test at line 319) did not reproduce in the before-run.

## After the edits
- (a) `sidebar-context-menu.spec.ts --repeat-each 10 --output test-results/F4`: 110 passed, 40 skipped, EXIT 0. The floating-sidebar flake did not recur.
- (b) `popover-bounds.spec.ts tests/motion.spec.ts --repeat-each 5 --output test-results/F4b`: 60 passed, EXIT 0. "toolbar popovers keep their recorded untouched-tree placement" passed 5 of 5.
- (c) `npx tsc -b`: EXIT 0, no output.

## Limitations
- The before-run did not reproduce the one-frame race, so the fail-first proof is weak: the fix is proven not to break the spec, not that it fixed a failure we saw.
- The floating-sidebar flake (Save click detached) is unexplained and may come back in the validation rerun.
- Browser runs were on the dev server (port 1449), not the built app. The built-app proof is for the validation rerun.

## Hand check
1. Start the dev server on port 1449 and open the app.
2. Turn on Reduce Motion in macOS settings.
3. Right-click a section in the sidebar with the mouse. The menu should appear at once, not fade in.
4. Open the menu with Shift+F10 on a focused row. It should appear as before.
