# B3 -- Standalone icon magnification

What changed:
- `src/components/icon-magnify.css`: one rule for the direct `svg` or `span` child of `.icon-grow`, `.project-row .delete-entry`, `.open-beside` and `.collection-open-beside`. Hover and keyboard focus scale that child to 1.25. The button itself is never transformed. Reduced Motion removes the scale.
- `src/hoverEmphasis.test.ts`: case (c) gets one narrow exception for that icon rule only (file `src/components/icon-magnify.css`, selector ending in `> :is(svg, span)`, body `scale(1.25)`). Nothing else is loosened. A doctored button-level scale makes case (c) fail.
- `tests/w9-icon-magnify.spec.ts`: new spec. Fail-first evidence is in `B3-fail-first.txt`.
- Fixture fixes in the spec: keyboard focus is finished with Shift+Tab then Tab (focus-visible needs keyboard input), and each button is scrolled into view before its box is measured.

What a user sees:
- Hovering or keyboard-focusing a standalone icon (project trash on the Projects page, sidebar Open beside in list and card view, and any `.icon-grow` icon) makes only the icon grow to 25 percent. The button does not move or resize.
- With Reduce Motion on, the icon does not grow.

Limitations:
- The Projects-page trash button does not carry `icon-grow` yet; it gets the grow through `.project-row .delete-entry`. T274 (P1) adds `icon-grow` to Projects page buttons; this task did not edit ProjectLibrary.tsx.
- Chromium only. Native WebKit rendering is not checked.
- The exception in `hoverEmphasis.test.ts` is owner-requested (25 percent icon grow, PLAN "Rules in force"); D1 amends the AGENTS.md sentence.

Hand check (not performed by me):
1. `npm run dev`, open Projects. Hover the trash on a project row; only the icon grows.
2. Tab to a trash button; only the icon grows.
3. In sidebar list view and card view, hover the Open beside icon; only the icon grows.
4. Turn on Reduce Motion; repeat 1-3; nothing grows.
