# T3 Reliability review

Reviewed 2026-10-19 against the approved plan and source at `f324a7a`. The four pre-existing owner-edited documentation files were preserved. This review changed no source or tests.

## Result

I found no confirmed writing-loss defect in the inspected edit, queue, journal, SQLite, mirror, close, or restoration paths. The focused frontend and Rust store suites passed. Three meaningful evidence gaps remain: additive metadata is not tested through sparse native saves and history/mirror paths; a restore test does not prove the pre-restore safety copy is usable; and the native harness does not drive the actual window-close callback or a failed-mirror close attempt. These are coverage gaps, not reproduced product defects. Their reachability is real, but the suspected failure behavior has not been observed.

## Persistence trace

1. `src/App.tsx:264-278` applies immutable project changes, increments the project revision, updates the active in-memory project, and enqueues it. `src/save-queue.ts:174-212` records changed entries and the header synchronously in WebView local storage before scheduling the trailing 250 ms save attempt and the 2,000 ms maximum-wait attempt. The maximum wait bounds a healthy queue's attempt time, not completion time or a hard loss window.
2. `src/save-queue.ts:214-260` serializes writes, sends changed entries with the confirmed base revision, preserves the journal on errors, retries from a full project when disk state is unknown, and removes journal keys only after the current journal revision has persisted. `src/storage.ts:46-67` routes desktop writes to Rust; browser preview stores one project blob under `folio.preview.*` and is not native persistence.
3. `src-tauri/src/store.rs:277-376` validates the header and entries, applies a delta in an immediate SQLite transaction, rejects stale/conflicting revisions, archives the previous revision, checks the completed entry set and section order, writes the header, commits, then marks the project for a mirror pass. SQLite is configured for WAL and `synchronous=FULL` at `src-tauri/src/store.rs:157-187`.
4. The mirror worker runs every three seconds (`src-tauri/src/lib.rs:11-12,148-156`). `src-tauri/src/store.rs:666-733` removes pending IDs while it reads the committed SQLite state outside the store lock, atomically replaces `project.json`, `manuscript.txt`, and `fragments.txt`, and requeues failures. `src/App.tsx:510-529,1957-1973` surfaces mirror errors and offers Retry; `saveAll` flushes the queue and the active project's mirrors (`src/App.tsx:288-293`).
5. Before opening another project, `src/App.tsx:337-435` flushes the queue, loads SQLite, reconciles the journal, and enters the recovered state. Library navigation calls `saveAll` first (`src/App.tsx:988-995`). Native close prevents the event, flushes the queue, then invokes `finish_quit` (`src/App.tsx:463-488`); the native exit-request route does the same through `folio:quit-requested` (`src/App.tsx:489-509`). `finish_quit` synchronizes all pending mirrors before permitting exit (`src-tauri/src/lib.rs:30-40,197-203`).
6. Entry deletion, version restoration, and passage restoration flush first and create a named safety snapshot before mutating the active project (`src/App.tsx:636-659,841-864,1029-1061`). SQLite snapshots and version reads are implemented in `src-tauri/src/store.rs:378-462`. Restore creates a new revision; current writing remains available in the snapshot if the later save succeeds or fails.

The journal uses WebView local storage, whose write-to-disk timing is controlled by WebKit. The architecture explicitly limits it to reload and in-app recovery guarantees; a hard process termination is only evidence for that particular run, and does not establish power-loss durability. SQLite `FULL` sync likewise does not establish physical power-cut behavior on macOS.

## Open coverage findings

### REL-01 -- Sparse saves and restore paths do not have a metadata round-trip assertion

- **Severity / type:** Medium, coverage gap only; no data-loss defect reproduced.
- **Boundary and reachability:** Project and entry additive fields are supported by the TypeScript model and Rust flattened serde maps (`src-tauri/src/store.rs:27-52,97-129`). They travel through the native save/recovery/history/mirror boundary in ordinary use.
- **Expected / observed:** Additive metadata should survive a sparse `save_changes` delta, history and named-snapshot reads, and the portable JSON mirror. `extended_project_metadata_survives_save_and_restart` (`src-tauri/src/store.rs:1319-1331`) verifies custom project and entry metadata after a full save and reload. `delta_saves_rebuild_the_project_from_entry_rows` verifies sparse entry deltas but uses ordinary text fields. No observed loss; the combination is untested.
- **Reproduction status:** Not reproduced; existing tests passed. This is an assertion gap, not evidence of a current failure.
- **Minimal test:** Extend `src-tauri/src/store.rs` with a synthetic project carrying custom project-level and entry-level fields. Save it, take a named snapshot, then issue a sparse delta that changes a different entry while retaining the custom fields. Assert full equality after `read`, history and named snapshot retrieval, and after `sync_mirrors` by parsing `project.json`. Do not change the schema or Rust field model.
- **Affected source:** Current local source at `f324a7a`; no affected release range established. **Owner decision:** none.

### REL-02 -- UI does not prove the safety copy made before a restore is usable

- **Severity / type:** Medium, coverage gap only; no restoration defect reproduced.
- **Boundary and reachability:** `restoreVersion` flushes and snapshots the current project before applying the preview (`src/App.tsx:841-864`). The native smoke restores an earlier named snapshot, but its final assertion checks the restored prose, not the safety snapshot containing the pre-restore state. `tests/writing.spec.ts` also restores an earlier snapshot without reopening the pre-restore safety copy. Entry deletion does have a direct safety-snapshot recovery check in `tests/housekeeping.spec.ts`.
- **Expected / observed:** After restoring an older version, the immediately previous writing should be selectable from the generated `Before restoring …` snapshot. The call order supports this; the recovery route is not asserted.
- **Reproduction status:** Not reproduced; the existing focused suites passed. This is an untested promise, not evidence that the snapshot is absent or wrong.
- **Minimal test:** Extend `tests/writing.spec.ts`: save text A as a named version, change the live project to text B, restore A, open `Snapshots & history`, preview the generated `Before restoring …` version, and assert B is present in that preview. Browser execution is useful UI evidence, but it does not establish native SQLite behavior.
- **Affected source:** Current local source at `f324a7a`; no affected release range established. **Owner decision:** none.

### REL-03 -- Current native rehearsal does not cover the actual window-close or failed-mirror close path

- **Severity / type:** Medium, native integration coverage gap only; no close/data-loss defect reproduced.
- **Boundary and reachability:** The Tauri window-close listener at `src/App.tsx:463-488` and the run-event listener at `:489-509` both flush before `finish_quit`. The native smoke exits by calling `app.exit` through `smoke_report`, which exercises the run-event route. `Store::mirror_failure_can_be_retried_without_losing_commit` proves mirror errors are retained for retry; `finish_quit` propagates a mirror failure before setting `ExitAllowed`. No existing run proves a user window-close request stays blocked when queue flush or mirror synchronization fails.
- **Expected / observed:** A real native close should remain open on save or mirror failure, retain SQLite and any uncommitted journal state, and permit exit after repair and retry. Static control flow and lower-level tests support this expectation; no failing behavior was reproduced.
- **Reproduction status:** Not reproduced. No native GUI or process was started in this review. The existing three-phase artifact is historical and does not cover this branch.
- **Minimal rehearsal:** In an isolated `FOLIO_SMOKE_DIR`, create synthetic writing and leave a journaled edit. Exercise the actual window-close request and verify the current text reaches SQLite and the JSON mirror before exit. In a separate isolated case, force a mirror destination failure only in the harness-owned project, request close, verify the window remains and SQLite plus journal remain recoverable, remove the obstruction, retry, and verify clean exit, `PRAGMA integrity_check=ok`, current prose, metadata, and mirror equality. Never use a real project or terminate an unowned process. Keep power-cut claims out of the result.
- **Minimal exact files if automated:** `tests/native-smoke.js`, `scripts/native-smoke.py`, and only if a test seam is required `src-tauri/src/smoke.rs`; no application change is indicated by this review.
- **Affected source:** Current local source at `f324a7a`; no affected release range established. **Owner decision:** T6/native access is still required; no policy or schema decision indicated.
