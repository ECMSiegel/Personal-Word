## Approach
1. **One row model.** Every Manuscript, Fragments and Research row is `[16 px icon][label]...`; Research rows get icons (Bibliography `Library`, source `Book`, note `StickyNote`, PDF `FileText`; implementer confirms each name exists in lucide-react 0.468 and otherwise uses `FileText`). A PDF row is depth 1: `padding-left: calc(var(--space-2) + var(--space-4))`. Rejected: spacer-only (the owner likes the Manuscript look and an icon also identifies the row kind).
2. **Reorder = drag + Option+Up/Down.** Fragments reorder inside `project.entries` keeping the other entries' slots; sources and notes reorder inside their arrays. Research rows get two sub-containers (`.entry-sublist[data-list="sources"|"notes"]`, `display: contents`) each with its own `useDragReorder`; Bibliography is a fixed first row (not draggable, not a drop slot); a PDF row rides inside its source's draggable unit (`.entry-unit`). Keyboard: Option+Up/Down on the focused `.entry-main` or `.group-title`; instant; announced in one `role="status"` `.visually-hidden` live region; focus stays on the moved row. Rejected: keeping the arrows hidden (owner asked for removal), a "move mode" key (more steps than one chord).
3. **Lines for every row, magnified by pointer.** `useSpyDock(containerRef)` (in `scrollspy.ts`) writes `--spy-mag` (0..1) on each `.spy-line` from the pointer's vertical distance: `spyMagnify(dy) = (dockScale(dy, SPY_RADIUS) - 1) / (DOCK_PEAK - 1)` with `SPY_RADIUS = 84` (about 2.5 rows) and the existing `DOCK_PEAK`. CSS length = `lerp(state length, 1, mag)`, thickness `1 + mag` (2 px to 4 px), transform only. Keyboard focus on a row sets that row's mag 1 and its neighbours 0.5 and 0.2 (instant). Off under Reduce Motion and touch. State meaning (all groups): `idle` row not open, `open` row open in the other split pane, `active` row open in the focused pane (or `readActiveId` in Read mode). Progress: only where a scroller exists (open section/fragment in write mode, active section in Read mode); drawn as a muted `::after` remainder shrinking right-to-left (the button keeps `background: accent`, base length 1, so the existing specs' contract holds). Research rows: lines show idle/open/active only (no progress).
4. **Research panel.** CSS-only layout fixes plus a labelled note field; then convert `research.css` to spacing tokens and add it to the token sweep. The dropdown fix is general, in `Popover.tsx`: find the nearest ancestor that scrolls (`overflow-x/y` is `auto` or `scroll`), measure placement against its box as well as the window, and clamp `max-width` to its width minus 16. Rejected: portalling menus to `document.body` (breaks `closest(".popover")` item logic, tests and the morph anchoring).
5. **Citation logic shared, not copied.** Extract to `src/research/citationActions.ts` (pure data transforms, unit-tested), `src/research/useLookup.ts` (the async lookup hook with the `latest` ref) and `src/research/SourceForm.tsx` (the fields block, `variant: "full" | "card"`). `ResearchPanel` is refactored onto them first (behaviour unchanged), then the card uses the same pieces.
6. **Floating = a layout mode, decided by measured room.** Preference `floating` (additive field in `folio.workspace.sidebar`, default false, global). `src/components/floating.ts` holds pure rules and one hook `useMarginFit`. Fit rule: for the left (sidebar) and right (card) side separately, `available = margin - 2 * FLOAT_GAP` where `margin` is the distance from the workspace edge to the document column's edge, `FLOAT_GAP = 16`. Document column = the white sheet's outer edge in page view; the text's own left/right edge in continuous view (so floating text never sits against characters); the Read column in Read mode. Sidebar fits when `min(prefs.width, available) >= 190` and then uses that width; card fits when `available >= 280` (card width `min(360, available)`). No document column (Settings, Comments, Bibliography, Projects, History, Versions open) or split view with two panes: does not fit, normal panel. Vertical extent: from the bottom of the format bar (focus mode: bottom of the reveal band) to the top of the footer, so the topbar buttons (Toggle sidebar, Snapshot, export) and the toolbar are never covered. Unpinned + hover-reveal keeps working: when it fits it fades/slides in as bare text; when it does not fit it is the existing overlay panel. Rejected: always overlay (would cover text), shrinking the page to make room (changes layout and page parity).
7. **No background at all on the floating sidebar.** Text on the desk (`--surface`, page view) or `--paper` (continuous). Hover/focus use the shared emphasis only. Card view cards keep their wave-4 paper+border fill (a recorded content-surface exception) -- see open question 3. Contrast of `--muted`, `--accent` and the Color-palette tints on `--paper` is measured in C3 (wave 3 measured them on `--surface`/`--sidebar` only).
8. **The citation card is a raised surface** (the same `--elevation-raised`, 1 px `--line`, `--shadow-raised`, square) because it holds inputs and menus; it is the one floating thing with a surface and the owner's "no panel" instruction applies to the sidebar. See open question 2.
