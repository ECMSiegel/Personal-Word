Date: 2026-10-28 | Architect: Claude Code (Sonnet 5.5, for coordinator) | Project: Project 13 - Word Processor | Status: APPROVED (owner 2026-10-28, defaults accepted)

## Goal
A writer opens the app after wave 3 and finds page view that keeps its page breaks at any zoom and never lets the caret or an empty line sit in the grey gap, every text button, link, tab, menu row and sidebar row going bold and growing slightly on hover and keyboard focus by one shared rule, split panes that each carry their own aligned footer, a sidebar that bolds and colours the section header and bolds only the open entry, toolbar icons that magnify like a dock, a scrollspy line rail that follows the reading position, and a focus mode that also hides the toolbar until it is needed.

## Definition of done

- Snapshot has no box border; it looks like its neighbours and gets the shared treatment (Playwright + screenshot).
- Split divider line and both pane-header rules meet on the same pixel column with no gap or overshoot (Playwright pixel check + screenshot).
- A fragment open in a split pane shows no "Give these words a home" strip; a fragment opened unsplit still does.
- In sidebar groups Manuscript, Fragments and Research: the group containing the open entry (main pane, or either split pane) shows a semibold, coloured header (section tint in Color, accent in Plain) and the open entries are semibold in the text colour; entries not open and headers without an open entry are unchanged; AGENTS.md and design-system.md state the new rule (Playwright; docs).
- Split view: each pane shows "Section page N of M" at its left foot and its own word count at its right foot, for that pane's own section; unsplit shows the same footer once. All footers use one hairline-ruled strip aligned to the pane header's gutters (Playwright + screenshots).
- Toolbar icons magnify with neighbour falloff under the pointer, show the same peak on keyboard focus (without motion), and do nothing under Reduce Motion (Playwright + screenshots).
- The sidebar's Manuscript list carries a scrollspy line column: one short line per section beside its row, the line of the section you are in (open in Write mode, or at one third of the viewport while scrolling in Read mode) expanded and in the accent colour, lines of sections open in a split pane half-expanded, hover or row focus expands a line, clicking a line opens the section (Write mode) or eased-scrolls to it (Read mode); the lines hide with the sidebar, never clip, and follow the sidebar's width, collapse and drag-reorder (Playwright; native screenshots).

## Approach
Eleven independent concerns, grouped into lanes so they run in parallel, with the shared hotspot files serialised.

1. **Zoom (item 1): make measurement independent of CSS zoom.** `computeBoundaries` temporarily sets `paper.style.zoom = "1"` (only when the computed zoom is not 1), measures everything in unzoomed layout px with no `ratio`/`scale`/`precise` heuristic, then restores the value in a `finally`, all in one synchronous task (no paint between). Both engines then report layout values in the same space, which is the space the page geometry variables are in. Rejected: tuning the `scale` heuristic per engine (guessing already failed once and cannot be tested in Chromium); replacing CSS zoom with `transform: scale` (breaks scroll height and the narrow-pane fit, large change); measuring in a hidden unzoomed clone (doubles DOM, breaks decorations). Cost: two extra style recalcs per measure when zoom != 1; guarded by the existing performance spec. G1 first proves the cause natively; if the native probe at zoom 75 is already correct on the untouched tree, stop and ask (the diagnosis would be wrong).
2. **Real page boxes (item 2): enforce one invariant, find the real intruder first.** Invariant "text-area": every caret position's rectangle, every empty paragraph and every line box lies inside a page's text area `[p * pitch + margin, p * pitch + margin + contentHeight - reserve]`, except the middle lines of a block taller than a page. Keep one document and the current spacer widgets (undo, find, selection untouched). A seeded fuzz of Enter/typing/Backspace/Delete/Shift+Enter/undo at three zooms asserts the invariant after each settle and fails on the untouched tree (that failure IS the diagnosis). The fix targets the found cause and adds a pure, unit-tested `gapIntrusions(blocks, plan, geometry)` guard run after `planPages`: if a non-overlong block still overlaps a gap, re-plan with a forced boundary before it (bounded to 3 passes, same pass count as the existing follow-ups). Also: Enter keymap in page view moves the caret with `scrollIntoView`; `clickSpacer` and `arrowAcrossGap` are kept and gain tests; mousedown, touch and drag-select inside a spacer resolve to a page edge. Rejected: separate DOM page wrappers per page (breaks one-flow editing, undo, find, footnote layout, ~everything wave 3 shipped; the owner chose "one document"); making the spacer a node in the document (pollutes saved content).
3. **One hover rule (item 3, coordinator addition): a catch-all with an exclusion list.** Tokens on `:root`: `--emph-weight: 600`, `--emph-scale: 1.04`, with `--duration-fast` and `--ease-out`. One block in `src/styles.css` ("Text-control emphasis") targets `button`, `a[href]`, `[role="tab"]`, `[role="menuitem"]`, `[role="option"]`, `summary` and `.text-action` on `:is(:hover:not(:disabled), :focus-visible)` and sets `font-weight: var(--emph-weight)` and `--emph-s: var(--emph-scale)`; `transform: scale(var(--emph-s, 1))` with a transition on `transform` only; the existing `button:active` press becomes `scale(calc(var(--emph-s, 1) * 0.99))`. The exclusion is one `:not(:is(...))` list: the icon-only controls (the six-times-repeated icon list at `src/styles.css:262-390`, `.toolbar-icon`) -- those keep the wave-3 colour rule, and toolbar icons get the dock. Existing weight-only hover rules for rows (`styles.css:1989-2000`, popover and dropdown items, project rows, template choices) are deleted so there is exactly one place that sets hover weight. The font-weight change reflows the label by about 3-5 percent; default (Q4): accept it, reserve nothing, because the controls sit in `gap`ed flex rows with `flex-shrink: 0` (set where the check finds a neighbour moving by more than 2 px). Rejected: `-webkit-text-stroke`/`text-shadow` fake bold (looks different from real semibold, differs between engines); width reservation through a hidden `::after` copy (needs a `data-label` on ~100 buttons); scale-only (owner asked for bold). Reduce Motion: the transition is removed, weight and scale still apply instantly (feedback is kept, motion is not). Disabled controls: none. Danger and accent colours are not touched, so `.is-danger`/`.delete-entry` stay red.
4. **Dock versus text treatment (precise boundary).**

| Control | Gets |
|---|---|
| `.format-bar .toolbar-icon` (icon-only buttons in the formatting bar, including icon buttons inside the split toolbar) | dock magnification (K1) plus the existing colour rule; NOT the text treatment |
| Dropdown triggers in the bar (zoom, paragraph, font, size field), the More button's popover rows, every Popover/Dropdown menu row | text treatment (they carry text) |
| Icon-only buttons everywhere else (sidebar group actions, tab close, pin, trash, split close, library display) | wave-3 colour rule only; no scale (icon list exclusion) |
| Every control that shows text (buttons, tabs, sidebar rows, project rows, settings controls, Snapshot, Append to section, Delete note, Open beside, Remove PDF, primary buttons) | text treatment |

   A button with both an icon and text (Snapshot, "Open beside" with icon if any) is a text control. The exclusion list is the single place that decides; the Playwright spec classifies each hovered element by whether it has visible text.
5. **Per-pane footers (items 8, 9).** One `PaneFooter` component (`src/components/PaneFooter.tsx`, `pane-footer.css`): a 32 px (`--control-height`) strip, `border-top: 1px solid var(--line)`, `--type-small`, `--muted`, tabular figures, status text at the left, word count at the right, horizontal padding equal to the pane header's (`var(--space-3)` left, `var(--space-2)` right in split; `var(--space-5)` unsplit, matching the top bar).
