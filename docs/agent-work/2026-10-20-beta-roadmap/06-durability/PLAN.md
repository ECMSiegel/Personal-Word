# PLAN -- Native failure coverage and evidence-based beta qualification
Date: 2026-10-20 | Architect: Codex | Project: Personal Word | Status: APPROVED -- owner: “Run the plan as cheap is as feasible utilizing luna as much as possible” (2026-10-20)

## Goal
Writers can recover acknowledged writing, detect failed saves and restore complete projects without the app overstating protection against a shutdown or disk failure.

## Request
Address the saving/shutdown limitation, close recorded reliability coverage gaps, and qualify new metadata/assets before a downloadable alpha or beta.

## Definition of done
Native tests cover actual close/error paths, acknowledged checkpoint crashes and journal conflict recovery; metadata and media survive all persistence routes; snapshot restore leaves a reopenable complete pre-restore copy; normal exports/builds and owner checks are recorded independently from browser tests. Required unknown checks remain blockers for the affected binary claim.

## Non-goals
Physical power-cut of owner's computer, destructive testing on real libraries, absolute zero-loss/hardware-failure guarantees, background cloud backups, removing recovery data to make tests pass, treating localStorage as fsync-backed disk storage.

## Context (verified)
- WAL/FULL connection setup -- `src-tauri/src/store.rs:173`; platform-specific FULLFSYNC caveat and journal scheduling limits -- `docs/architecture.md`, Save/history/recovery. [SQLite docs](https://sqlite.org/pragma.html#pragma_fullfsync) describe platform support, not an immunity guarantee.
- Native runner kills only its process after an acknowledged checkpoint, then checks recovered text and integrity/mirrors -- `scripts/native-smoke.py:116-173`.
- Existing test covers full metadata save/restart -- `src-tauri/src/store.rs:1319`; sparse metadata/history/mirror combinations, reopened pre-restore copy and actual window-close during mirror failure remain recorded gaps -- `docs/agent-work/2026-10-19-alpha-security-reliability/FINDINGS.md`, REL01-03.
- Restore flushes/snapshots before mutation -- `src/App.tsx:1029-1057`; mirror status is a separate error route -- `src/App.tsx:510-529`.
- Existing source-only manual native-sidebar gap was accepted, not owner-confirmed working -- prior qualification review and HANDOFF latest state. That waiver does not carry to binary distribution.
- Physical sudden-power-loss outcome and Apple silicon real-use evidence are UNKNOWN, regardless of successful source tests.

## Rules in force
Parent/project writing preservation and native proof boundaries. Every fault injection operates only inside an owned temp root and kills only its recorded child process group. No chmod/rename/delete outside that root, no global filesystem/network/printer changes. All native/test-only fault hooks compile behind native-smoke and must be absent from normal release.

## Approach
D1 qualifies and minimally hardens the existing save model for the early download. D2 repeats and extends the matrix after schema/features arrive. Prefer evidence-led small fixes over replacing SaveQueue or the persistence architecture. Keep current fsync limitations, uncommitted edit windows and external-backup need explicit even after better testing.

Explain failures as product/test/environment cases with evidence, not generic “flaky.”

## Risks and rollback
Keep online backups before schema changes and safety snapshots before restore/merge. Test faults are cfg-gated and normal binaries must reject/omit them. Preserve data when recovering from newer schema; never open active upgraded DB in an older app for rollback. If checksum/integrity fails, keep original store and recover a copy; no corruption reset. FULLFSYNC can improve platform flush behavior but cannot promise surviving hardware/OS failure; external backups remain necessary.

## Open questions for the user
Intel/Apple silicon and Word/native real-use testers required for affected release claims. Physical power-loss guarantee is excluded, not a checkbox to bypass. No owner task is required to author this plan; execution/release approval and hardware access are later gates.

## Notes for the implementer
Keep acknowledged SQLite commit distinct from WebView journal, scheduled save attempt, portable mirror and external backup. Sparse-save metadata test presence is not proof of all new-field paths. A successful browser recovery says nothing about native WebKit disk scheduling. Never count a source-only acceptance as a binary install test.
