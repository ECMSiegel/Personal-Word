# PLAN -- Safe rich imports and portable document assets
Date: 2026-10-20 | Architect: Codex | Project: Personal Word | Status: APPROVED -- owner: “Run the plan as cheap is as feasible utilizing luna as much as possible” (2026-10-20)

## Goal
Writers can import documents containing pictures, tables and footnotes without losing their content or exposing their computer to imported active content.

## Request
Address text-only/5MB imports, absent DOCX/HTML conversion and Markdown note round trips; storage and export support must precede UI claims.

## Definition of done
New project previews show conversion warnings and content counts; cancel leaves no visible project; accepted images/tables/notes survive SQLite/journal/history/snapshot/archive/native restart and DOCX/PDF output. Original files remain untouched. No imported URL is fetched automatically. Markdown note references/definitions round-trip with supported project archives carrying images.

## Non-goals
Macros, scripts, OLE/ActiveX, embedded executables, executing raw HTML, remote-image fetching, arbitrary Word fidelity, merged/nested/advanced table editing in the first implementation, filesystem access beyond explicitly selected inputs. Legacy JSON recovery compatibility is not capped retroactively.

## Context (verified)
- Shared schema lacks table/image nodes -- `src/editor/extensions.ts:10-18`; native allowlist rejects them -- `src-tauri/src/store.rs:775-808`.
- Current Markdown disables tables/HTML and makes image syntax literal -- `src/import/manuscript.ts:5-7,36-65`; preview is synchronous with 5MB text ceiling -- `src/import/manuscript.ts:81-89`.
- Existing JSZip is dev-only; document export uses common Block/Inline representation -- `package.json`, `src/export/document.ts:18-54`.
- Project JSON portable mirrors and localStorage journal contain project metadata/prose -- `docs/architecture.md`, Model/storage and Save/recovery; binary asset storage is currently deferred there.
- Markdown exporter writes note definitions, importer doesn't parse them -- `src/export/textExport.ts:108-152`, `src/import/manuscript.ts:16-79`.
- Schema migration supports old databases and rejects newer ones -- `src-tauri/src/store.rs`; exact new migration behavior needs tests. Import parser library approval is UNKNOWN.

## Rules in force
Parent/project data preservation, shared schema/native validation and no silent loss. Integrator owns model/store/SaveQueue/manifest changes. No new dependencies/tools without separate approval. Source documents and user libraries remain read-only. Rich import defaults and size ceilings below are explicit new-import behavior, not existing-project truncation.

## Approach
Use content-addressed assets committed natively before an edit can reference them; never put binary payloads in the WebView recovery journal. Preview keeps bounded staged assets in memory, and confirmation atomically creates a new project and its assets. Add basic rectangular table/image nodes to existing Tiptap schema using its installed Node API. Use a real inert HTML parser, never DOM attachment or regex-only HTML sanitization. Gate exact dependency approval before new parser use; no guessed replacement if blocked.

## Risks and rollback
Online v2 database backup before migration; reject newer schemas in old app. Restore a copied pre-migration backup only into an isolated location for recovery. Never downgrade the user's active DB or delete staged/history assets to make rollback pass. Cap only new import tiers; old recovery remains compatible with documented resource risks. Preserve original source bytes and cancelled preview contents in memory only.

## Open questions for the user
Separate exact dependency installation permission at I2; no new package may be silently selected. Parent approval adopts the stated input tiers/basic table scope. Bigger tiers or advanced merged-cell editing need separate measured extension, not a validator bypass.

## Notes for the implementer
Content-addressed database assets solve a different problem from inline data URLs. A localStorage quota exception must never leave an image reference with no durable bytes. Missing assets are recovery errors with intact writing, not grounds to reset a project. PDF layout stage must later cover these same asset/table fixtures.
