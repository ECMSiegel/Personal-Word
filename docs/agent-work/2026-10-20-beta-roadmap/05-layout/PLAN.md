# PLAN -- Native typography and an exact PDF print preview
Date: 2026-10-20 | Architect: Codex | Project: Personal Word | Status: APPROVED -- owner: “Run the plan as cheap is as feasible utilizing luna as much as possible” (2026-10-20)

## Goal
Writers can inspect the exact PDF they will save, retain their chosen document typography and export long multilingual footnotes without clipping.

## Request
Address differing layouts, bundled-font-only PDF, unsupported shaping/scripts and overlong footnotes from the screenshot; preserve editable Word output and honest limits.

## Definition of done
Native print feasibility passes on actual macOS WebKit; new print preview displays the same PDF bytes that Save writes; explicit document font policy and tested script fallback are visible; footnotes continue over pages with no missing/duplicated text; image/table/citation content from I/C stages survives; Word output retains structural formatting with explicit reflow boundary.

## Non-goals
Guaranteeing identical editable Word pagination across versions/Macs, replacing the live editor with images, silently changing old export settings, proprietary font redistribution, promising every script/glyph available on any Mac. Browser-only print mocks are not native qualification.

## Context (verified)
- Editor uses CSS columns and uniform footnote reserve -- `src/editor/formatting.ts:111-144`, `src/editor/footnoteLayout.ts:22-29`; PDF independently computes pages -- `src/export/pdf.ts:129-300`.
- PDF rejects unsupported shaping and overlong footnotes -- `src/export/pdf.ts:61,285-288`; family mark metadata exists -- `src/editor/formatting.ts:3-25`, `src/export/document.ts:22-33`, but current PDF selects bundled families.
- UI prefers local Futura/Avenir per project AGENTS.md; document font is independent. Existing export settings lack a renderer/font policy -- `src/research/types.ts:45-61`.
- WKWebView exposes [printOperation(with:)](https://developer.apple.com/documentation/webkit/wkwebview/printoperation(with:)); this is a verified API, not evidence of this app's paginated/footnote behavior. Suitable bridge dependencies and actual native output are UNKNOWN until L1.
- E/C/I task contracts supply precise quote/citation, assets and rich blocks; run their relevant integrations before L2/L3 final acceptance.

## Rules in force
Parent/project preservation, separate reading/export settings, native checks and normal rebuild. Integrator owns Rust commands/config/dependencies and shared document/settings contracts. New native bridge/font installations require separate explicit approval. No broad file://, network or IPC access for the print view. No removal of legacy renderer until old-project migration is validated.

## Approach
Introduce a versioned native-v2 print path behind an opt-in per-project setting. Reuse normalized document blocks plus native WebKit text measurement for a deterministic paged print document; send sanitized generated page markup to a locked-down native print operation. Preview consumes the resulting PDF, not a separate approximate HTML reflow. Keep the editable draft page view clearly labeled as such; DOCX remains a semantic editable document with paper/margins/manual breaks, not a fixed-layout guarantee.

## Tasks

Native command `render_pdf` validates snapshot/schema, bounds HTML/output and resolves only that snapshot's approved asset IDs. Print view has no app IPC bridge, JS from imported content, arbitrary navigation, file URLs or external requests. Existing save-file dialog remains separate from rendering.
- Steps: (1) Confirm available WebKit/AppKit bridge APIs and exact compatible crate versions in a minimal proposal; request missing dependencies before installation. Choose WKWebView.printOperation with NSPrintInfo save-to-PDF, not createPDF on a tall viewport assumed to paginate. (2) Implement isolated print view from schema-generated escaped markup, script execution disabled, CSP default-src none with only approved inline styles/data fonts/images, blocked navigation/remote fetch; native operations on required UI thread. Host passes a validated immutable in-memory snapshot after normal save flush; export must not mutate the project or claim stale revision bytes. (3) Probe Letter/A4 fixed pages, explicit breaks, header/footer geometry, a note continuation, tables/images and mixed-direction text with available fonts. Wait for real font/image completion before measurement/printing; prove readiness rather than sleeping. (4) Extract/render the actual PDF and compare page boxes/text/content with probe contract. No whole-document rasterization: text selection/search must work. (5) Keep legacy export reachable if any probe fails; record exact failing capability and revise this plan with owner before adopting a different renderer.
- Acceptance check: fresh isolated `npm run tauri build -- --debug --features native-smoke --no-bundle --config '{"identifier":"com.folio.smoke"}'`, then `python3 scripts/native-print-smoke.py --probe` -> actual WebKit output has expected Letter/A4 page boxes/counts/manual breaks, searchable Unicode text, expected media/table content and zero remote/file loads. Render all probe pages and inspect actual script ordering/ligatures, not only code-point counts. Full normal rebuild occurs after diagnostics before offering an app.
- Fail-first: deliberately feed a one-tall-page result, missing font readiness, external resource and raster-only PDF to the probe checker; each must fail its distinct assertion before native result passes.
- Stop and ask if: native print cannot satisfy pagination/searchable shaping without unsafe privileges, font readiness is unobservable, or approved bridge dependency unavailable.
- Default if unanswered: retain legacy PDF and label new path experimental/unavailable; do not remove script/long-note warnings or claim parity.

### L3 -- Per-page footnote allocation with continuation
- Files: create `src/print/pagination.ts`, `src/print/pagination.test.ts`, `src/print/footnotes.ts`, `src/print/footnotes.test.ts`, `tests/fixtures/print/` synthetic long-note/multilingual/media fixtures; modify `src/print/document.ts`, `src/print/print.css`, `tests/native-print.js`, `scripts/native-print-smoke.py`, `src/export/document.test.ts`. Do not rewrite live editor CSS columns in this task; editable layout remains independently qualified.
- Interfaces: `paginateMeasuredDocument(document, measurements, geometry): PrintPage[]`; measurements are native WebKit line/grapheme boxes at exact print font/geometry. `PrintPage` includes body slices and `NoteSegment {noteId,number,from,to,continuedFromPrevious,continuesNext}`; slices preserve stable source ranges and directional shaping. Limits: max10000pages then a clear export error, never truncation; normal note area <=40% content height, continuation-only pages may use available height.
- Steps: (1) Measure body/note lines after assets/fonts ready, grapheme-safe across bidi text; preserve list counters/quote nesting/inline marks. (2) Allocate each page's notes from its own references, not the tallest note on another page. Keep at least two note lines with the first reference where possible; move reference/body slice to next page if necessary. (3) Split long notes at measured line boundaries and emit labeled continuation segments; allow continuation-only pages if a note exceeds the normal note area. Page allocation advances monotonically through source ranges with bounded backtracking; assert no oscillation or repeated identical progress state. (4) Reserve continuation notes before placing next page's body/new references; every note source range appears exactly once across segments and every reference resolves. (5) Preserve explicit breaks, orphan/widow constraints where declared, huge words and image/table row handling; indivisible oversized objects produce an explicit scale/warning policy, never clipping. (6) Compare extracted PDF note text/source offsets and rendered pages, including notes longer than two pages, several notes on one page and mixed-script tables/quotes.
- Acceptance check: `npm test -- src/print/pagination.test.ts src/print/footnotes.test.ts`; `python3 scripts/native-print-smoke.py --matrix` after diagnostic build -> exact full body/note text coverage, zero duplicated/missing segments/overlaps, all refs resolve, continuations labeled, page boxes consistent and finite. Render every adversarial page and verify visual notes/rules/RTL; native preview/save buffers identical. Export no longer refuses the supported long-note fixtures.
- Fail-first: legacy exporter fails overlong-note fixture; remove segment advancement/reserve in an isolated copy to prove duplication/overlap checker fails, then restore fix. A text-only proof cannot replace page overlap inspection.
- Stop and ask if: a content shape cannot be split safely, measured page allocation fails to converge, or native measurement differs from printed font metrics beyond fixture tolerance.
- Default if unanswered: explicit export error with writing intact and DOCX alternative; retain warning and do not ship native-v2 as complete until required fixtures pass.

## Validation (after tasks, in order)
L1 native feasibility -> L2 font/privacy/preview identity -> L3 segmentation negative/positive controls -> full sequential build/unit/browser/Rust -> I/C export round trips and D2 durability -> all actual PDF/DOCX pages -> owner native print/font checks -> normal signed release rebuild and independent REVIEW.md. Print-view network interception must remain zero for hostile imported data.

## Risks and rollback
Renderer selection is versioned and opt-in for existing projects. Retain original content/settings/legacy exporter and safety snapshot. Rendered output is disposable, never writing source. Failed native print closes only its owned view and deletes only its owned temporary output if authorized; do not touch user projects or global printers. No browser “print to PDF” stand-in for native proof.

## Open questions for the user
Parent defaults require explicit acceptance of PDF-preview parity with editable DOCX reflow caveat and stated script matrix. Missing bridge/fonts require separately reviewed installation permission. If identical Word page breaks are a hard requirement, stop and re-scope before L2; this plan does not promise it.

## Notes for the implementer
WebKit createPDF is not assumed to produce paginated paper output. CSS footnote support is not assumed either; explicit measured note allocation is required. Native APIs being present do not prove this implementation's pagination, font readiness, searchable complex-script output or safe imported-resource handling.
