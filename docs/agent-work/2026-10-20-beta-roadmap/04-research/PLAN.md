# PLAN -- Broader sources and dependable research workflows
Date: 2026-10-20 | Architect: Codex | Project: Personal Word | Status: APPROVED -- owner: “Run the plan as cheap is as feasible utilizing luna as much as possible” (2026-10-20)

## Goal
Writers can bring in their research library, identify duplicates safely and choose consistent citation behavior throughout the manuscript and exports.

## Request
Address limited source types, inconsistent DOI handling, CSL-only import, weak duplicate decisions, absent BibTeX/local live updates and missing per-section/ibid options; keep citation verification explicit.

## Definition of done
Legacy three-kind records remain unchanged/readable; additional structured source records preserve imported fields; one shared identifier policy serves lookup/import/rendering; duplicate review never silently merges unlike works. BibTeX and opt-in read-only Zotero desktop refresh work offline from retained local records. All renderers use the same ordered note-context results and explicit manual overrides.

## Non-goals
Claims that metadata is always correct; hidden external requests; automatic correction of citations/instructor requirements; cloud/bidirectional Zotero sync; overwriting local edits or deleting sources based on remote deletion. No unreviewed citation processor license change.

## Context (verified)
- `Source.kind` is book/journal/website, legacy authors are natural-name strings -- `src/research/types.ts:1-22`; formatter uses surname heuristics -- `src/research/citations.ts:3-22`.
- Lookup already recognizes DOI URL, dx.doi.org and doi prefixes -- `src/research/lookup.ts:38-43,66-70`; CSL import independently normalizes DOI and checks CSL IDs/DOI/title+first author -- `src/research/cslImport.ts:63-84,104-111`; citation URL builder only strips doi.org -- `src/research/citations.ts:46-49`. README overstates the missing DOI/dedup functionality.
- Note resolver has manuscript-wide seen-source state, legacy shortened/manual overrides -- `src/research/noteForms.ts:25-47`; research form exposes three kind options -- `src/research/ResearchPanel.tsx:27-35`.
- Zotero local API supports opt-in local read endpoints -- [official docs](https://www.zotero.org/support/dev/web_api/v3/local_api). Actual owner Zotero version/library availability is UNKNOWN.
- A possible BibTeX parser upstream currently declares ISC in package metadata but has MIT LICENSE text -- [package metadata](https://raw.githubusercontent.com/retorquere/bibtex-parser/master/package.json), [license](https://raw.githubusercontent.com/retorquere/bibtex-parser/master/LICENSE). Exact published candidate/license/transitive suitability is UNKNOWN; do not install an arbitrary latest version.
- citeproc-js offers CPAL/AGPL -- [upstream license](https://github.com/Juris-M/citeproc-js/blob/master/LICENSE). This plan does not silently adopt it; extend existing formatter for the bounded types instead.

## Rules in force
Parent/project preservation and Chicago guidance, no punctuation rewriting inside user notes, manual override authority, no secrets/new packages without permission. Integrator owns types/model/App/storage bridges and coordinates I/E changes. Keep legacy note default behavior on old projects until explicitly changed.

## Approach
Add lossless optional raw CSL/structured creator fields while retaining legacy string author compatibility. Share canonical identifiers, compare complete creator/year/type information and present ambiguous duplicates rather than discarding them. Use one ordered citation-context builder for editor/preview/export. BibTeX goes through an approved real parser into the same import-review model. Zotero is an explicitly enabled, local, read-only source refresh with conflict review and retained local copies.
