# T4 -- Notes tab rework: no hint, one line between notes

## Plan & Implementation

1. **Removed hint**: Removed the paragraph `"Ideas and reminders. Quotes from a source live under that source."` from the Notes tab in `src/research/ResearchPanel.tsx`. The `"No notes yet."` message is preserved when there are no notes.
2. **Spacing from "Add note"**: Removed `margin-bottom: var(--space-3)` on `.note-actions` in `src/research/research.css`. The parent `.research-panel` grid gap (`var(--space-4)` = 16px) now directly spaces the `"Add note"` row to the notes list.
3. **Line divider & Spacing between notes**:
   - Wrapped the loose notes list in `<div className="note-list">` with `display: grid; gap: 0;`.
   - `.note-item` has `padding: 0; border-left: 0; gap: var(--space-2)` (8px internal gap).
   - The first note has no line above it (`border-top: 0`).
   - Consecutive notes (`.note-item + .note-item`) have `border-top: 1px solid var(--line)`, `margin-top: var(--space-5)` (24px above line), and `padding-top: var(--space-5)` (24px below line), cleanly isolating notes with `--space-5` spacing and a single divider line.
4. **Shared row for source dropdown and delete button**:
   - Placed the `"Attach to source"` dropdown container and `"Delete note"` button inside `<div className="note-row">`.
   - `.note-row` uses `display: grid; grid-template-columns: minmax(0, 1fr) auto; align-items: end; gap: var(--space-3);`.
   - The dropdown grows to fill the row while the delete button sits to its right, eliminating stacked divider lines.

## Why the old spacing floor changed (agent-9c65, closes the open flag)

The older "a note has a visible Note label" test used a 24 px floor (comment: it guarded the 12 px
`.note-actions` margin-bottom plus the panel gap). PLAN step 2 removes that margin, so the old floor
guarded something that no longer exists. That test now pins 12..20 px, and the new T4 test pins
16 +/- 2 px (the panel grid gap). Reason confirmed by the reviewer (Fable agent-9d19, r1).

## Spec rework after reject r1

The old check read only computed border-top on `.note-item`. It is replaced by a separate test,
"exactly one rendered line between two notes, no two lines within 8 px": it collects every top/bottom
border edge in `.research-panel` (textarea and dropdown button included), asserts exactly one edge lies
between note 1's dropdown bottom and note 2's textarea top, and no two edges outside `.research-tabs`
are within 8 px. The hint check is its own test so the line checks fail on their own against wave 5.
