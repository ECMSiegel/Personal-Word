## Goal
Personal Word looks and behaves like a deliberate, top-tier Mac writing app: every screen uses one type scale and one spacing scale, every control shows hover, focus, pressed, disabled and selected states, the writer can choose System, Light or Dark and a Plain or Color palette, and the Projects screen has an expanding search, a create button that grows into a menu, and drag-and-drop import.

## Approach
CSS custom properties carry everything. T1 adds `--type-*`, `--space-*` and motion tokens and sweeps the two named files onto them, with a unit test (`src/designTokens.test.ts`) that reads the CSS files and fails on any raw UI font size, any 4-32 px spacing literal in the swept files, and any UI size below 12 px anywhere. T2 adds one state recipe (`--focus-ring`, `--pressed`, `--disabled-opacity`) applied globally. T4 introduces `src/appearance.ts` (pure functions, unit tested in Node) and one global `localStorage` key `folio.workspace.appearance` = `{"theme":"system|light|dark","palette":"plain|color"}`, the same mechanism and naming family as the global sidebar key; it is applied as `data-theme` / `data-palette` on `<html>` in `main.tsx` before the first render, and the dark tokens move under `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }` plus `:root[data-theme="dark"]`. T5 adds `--accent-plain`/`--danger-plain` so document areas can pin today's colours while the Color palette overrides `--accent`/`--danger` and adds fill, success, warning and tint tokens. T7-T9 put Projects-screen styles in a new `src/components/library.css`. T9 reads dropped files natively through a new Rust command that only reads paths the window actually received in its last drop. T0 adds a smoke-build-only WebKit snapshot command so agents can take real native screenshots without Screen Recording permission.
