# PLAN — Layout primitives: one spacing system for the whole interface
Date: 2026-11-12 | Architect: Claude Code (Fable 5.2), inventory by Sonnet | Project: Project 13 - Word Processor | Status: APPROVED (owner chose "option 3, full migration" on 2026-11-12 and answered the open questions)

## Goal
Every bar, menu, popover, list row and icon button in Personal Word lines up and is evenly spaced because it is built from five shared layout pieces, and a test stops hand-made spacing from coming back.

## Request
Owner, 2026-11-12: "many of the issues we have been encountering is spacing related"; "I am keen on option 3" (full migration onto primitives; reversible); icon slots "sounds fine" (24x24 sidebar, 28x32 toolbar); "I want the title a bit bigger than the rest"; "more screens of poorly spaced popovers" (New-project menu); "'new top level section' should say something like 'add section' ... needs a new name" -> owner chose **Header**; "when you add a new section there is no way to change the color of the icon which we need".
Screenshots to fix by construction: Prose check popover rows touching; Saved/Snapshot/Export uneven and toolbar icons not sharing the right edge with Export; sidebar title/search/headings on different left edges; heading icon cluster vs entry-row icon cluster uneven and not in columns; New-project menu; the "+ New top-level section" row.

## Definition of done
- In the app: (1) sidebar title, search icon, heading icons and row icons share one left edge; the title is 15px, the rest 13px. (2) Heading action icons and entry-row action icons are 24x24 slots in shared right-hand columns with equal gaps. (3) The last ink of the top bar and of the format bar share one right edge; Saved / Snapshot / Export are evenly spaced. (4) Every menu (New project, Export, dropdowns, context menus, command palette) has the same row height, inset and separator spacing. (5) Every toolbar popover (Prose check, Line spacing, Page setup, zoom, font, paragraph style, table controls) has rows of one height with one gap; nothing touches. (6) Custom top-level sidebar sections are called "headers" everywhere; each has a "Colour..." menu item.
- `npx vitest run src/layoutPrimitives.test.ts` passes: per-file counts of hand-written spacing are at or below the budget, and no z-index >= 10 is a bare number.
- `tests/layout-invariants.spec.ts` passes against the built app.
- Full validation list at the end passes; a before/after screenshot gallery exists for the owner.

## Non-goals
- The document itself: paper, page geometry, rulers and tick marks, pagination spacers, footnote area, editor/Read prose typography, print CSS (`src/print/`, `@media print`).
- Colours, fonts, hover/emphasis rule, motion. The 6x repeated icon-button colour selector list (styles.css ~261-380) stays.
- Page header/footer feature (deferred by the owner; when built it is named "Page header"/"Page footer").
- Exports following the interface font; section-name headings in Read/exports.
- React layout components. Primitives are CSS classes only.
- Driving the budget to zero. Widths, dialog paddings and one-off geometry may remain if counted in the budget.

## Approach
CSS-class primitives in one new file, consumed by every surface; sizes come only from tokens; a budget test ratchets hand-written spacing down per file; a browser test asserts the alignment relationships themselves (shared edges, slot sizes, row rhythm) instead of recorded pixel numbers.
Rejected: an 8pt rule alone (the app is already on a 4px scale; none of the reported defects is an off-scale number). React layout components (bigger diff, same result). Pilot on four surfaces only (owner chose the full pass). Recording new pixel baselines as the main safety net (they pin numbers, not relationships).

### The system (decided; implementers do not change these)
Tokens added to `:root` in `src/styles.css` next to `--control-height`:
`--bar-height: 40px; --row-height: 32px; --row-height-compact: 28px; --slot: 24px; --slot-toolbar-w: 28px; --edge: var(--space-4); --edge-main: var(--space-5);`
`--layer-card: 39; --layer-bar: 40; --layer-popover: 45; --layer-overlay: 60; --layer-modal: 70;`
Classes in new `src/components/layout.css`:
- `.bar` — flex row, `align-items:center`, `height:var(--bar-height)`, `padding-inline:var(--edge)`, `gap:var(--space-2)`, border-box. `.bar-compact` — height `var(--control-height)`. `.bar-main` — sets `--edge: var(--edge-main)`. `.bar-divider` — 1px x 16px, `margin-inline:var(--space-1)` (was `--space-2`; narrowed 2026-11-12 so the format bar still fits one row at 1440, board Q032).
- `.stack` — flex column, `gap:var(--gap, var(--space-2))`; `.stack > *` has `margin-block:0`. `.cluster` — flex row, centred, `gap:var(--gap, var(--space-1))`, `flex:none`. `.gap-0 .. .gap-6` set `--gap` to 0 / `--space-1..6`.
- `.row` — flex row, centred, `min-height:var(--row-height)`, `padding-inline:var(--edge)`, `gap:var(--space-2)`. `.row-label` — `flex:1 1 auto; min-width:0`. `.row-trail` — a `.cluster` pushed to the end (`margin-inline-start:auto`). `.row-value` — right-aligned, tabular figures, `min-width:var(--value-width, 3ch)`.
- `.menu` — list surface: `padding-block:var(--space-1)`, `--edge: var(--space-3)`. `.menu-rule` — 1px line, `margin-block:var(--space-1)`. `.panel` — form-like popover body: a `.stack` with `padding:var(--space-3)`, `--edge: 0px`, `--row-height: var(--row-height-compact)`.
- `.slot` — icon-button box: inline grid, centred, `width:var(--slot); height:var(--slot); padding:0; flex:none`. `.slot-toolbar` — `width:var(--slot-toolbar-w); height:var(--control-height)`.
- `.flush-end` / `.flush-start` on a cluster of slots — negative inline margin of `(slot width - icon size) / 2` so the icon ink, not the box, sits on the edge.
Rules of use: a component never sets margin on itself; the parent's `gap` spaces children; text and icon ink start at `--edge`; any `z-index` of 10 or more is a `--layer-*` token; small local stacking (1-9) may stay literal.
Fixed numbers: sidebar and its popovers use `--edge` 16; main-pane bars (top bar, format bar, split header, pane footer) use `.bar-main` 24; project tabs become `.bar-compact` (32, was 34); menus use `--row-height` 32; panels use 28; toolbar groups have gap 0 with `.bar-divider` between groups; sidebar action clusters use `.gap-0` slots of 24.
