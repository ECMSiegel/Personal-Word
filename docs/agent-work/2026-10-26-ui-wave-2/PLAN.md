# PLAN -- UI wave 2: one motion engine, one popover, a calmer sidebar, split view, a live bibliography and source PDFs
Date: 2026-10-26 | Architect: Claude Code (Opus 5.5) | Project: Project 13 - Word Processor | Status: APPROVED

## Goal
Personal Word moves and reads like one deliberate Mac app: every menu, panel and selection animates the same quick, interruptible way (or not at all under Reduce Motion), the sidebar is quieter and configurable, and a writer can work on two pieces side by side, read a live bibliography, and keep a source's PDF open next to the manuscript.

## Request
Owner, 2026-10-26, decisions A-O settled and not to be reopened (summarised faithfully; quoted words are the owner's):
- A. Motion engine, quality first: hand-built `src/motion.ts` on the Web Animations API, no packages; animate only transform, opacity and clip-path ("never layout properties"); every animation interruptible and reversible mid-flight ("a reopened menu reverses from its current frame"); enter ease-out, exit ease-in, `--ease-spring` only for size changes; durations from tokens `--duration-fast` 120 / `--duration-base` 180 / `--duration-morph` 220, "nothing longer"; prefers-reduced-motion makes everything instant; a unit test over the CSS and a Playwright test that measures that no layout property animates and that reduced motion yields 0 ms; a presence helper so exit animations run before unmount.
- B. One Popover primitive (`src/components/Popover.tsx` + `popover.css`) used by Dropdown, the create menu, the toolbar overflow "more" menu and Sort: placement below the anchor with edge flipping, raised surface (page colour, 1 px `--line`, shadow), open = grow from the anchor edge 160-180 ms + fade, close = 120 ms ease-in, one sliding highlight that glides between items, item stagger 15 ms, pressed = scale 0.99 over 80 ms, right-aligned muted shortcut hints where a shortcut exists ("Cmd+B Bold etc."), Dropdown keyboard contract and tests unchanged.
- C. Create menu morphs in place over the button: the button fades, the menu grows from the button's own rectangle as an overlay (no header reflow), items staggered, close shrinks back into the button; built on B.
- D. Toolbar icon-and-text mode when the format bar container is >= 1100 px: a 12 px label beside each icon, grouped; icons only below; overflow keeps working in both modes (measure in both). Label slot and magnifying dock are non-goals.
- E. Elevation tokens page/surface/raised with a token test; one control height (32 px) and gap token for header rows (Projects header, writing breadcrumb row, format bar); one icon size (16 px, chevrons 14) and stroke everywhere; sliding selection highlight in Segmented and the sidebar (same engine as B).
- F. Settings gets three per-project switches to show or hide Read manuscript, Comments, Snapshots & history (Settings row always shown); bottom rows have a fixed order and no hover reorder/cards/add icons; only Manuscript, Fragments, Research keep group actions; persist with the existing per-project feature-order mechanism.

Section colours: in Settings next to Appearance/Palette, one row of three swatch pickers (Manuscript, Fragments, Research) choosing among eight Apple-system-derived swatches (red, orange, yellow, green, teal, blue, indigo, purple), each pre-darkened per mode to pass 4.5:1 on every surface; Color palette only; global; stored additively in `folio.workspace.appearance`.

## Definition of done
- Every animation in the app is either a CSS transition or a `src/motion.ts` animation that touches only transform, opacity or clip-path (visibility allowed as a discrete companion of the sidebar overlay slide); every duration is one of `--duration-press` 80, `--duration-fast` 120, `--duration-base` 180, `--duration-morph` 220; a unit test enforces this over every stylesheet, and a Playwright test (`tests/motion.spec.ts`) shows that opening the search, sidebar overlay, a Dropdown, the create menu, the More menu, a Segmented control and a sidebar selection animates only those properties, and that with Reduce Motion there are zero running animations and panels appear and disappear at once.
- A reopened menu continues from its current frame (no remount, no jump) -- proven in `tests/motion.spec.ts`.
- Dropdown, Sort, the create menu, the More menu and the toolbar panels all render through `Popover`: page-coloured raised surface with 1 px line and shadow, square corners, one sliding highlight, items opaque from the first frame, shortcut hints where a shortcut exists; every existing Dropdown keyboard test passes unchanged.
- "Start new project" opens a menu that covers the button and grows out of it; the header does not move.
- With the format bar at least 1100 px wide every toolbar icon shows its 12 px label (default reading of D, see open question 3); below that icons only; the More menu lists overflowed controls as labelled rows with shortcut hints; overflow is correct after crossing the threshold in both directions.
- Elevation, control-height, header-gap and icon tokens exist and a unit test checks them; every lucide icon is 16 px (chevrons 14) with the default stroke.
- The writing sidebar starts with the project title row (no "Personal Word" line), the bottom rows are Read manuscript, Comments, Snapshots & history, Settings in that fixed order with no hover reorder/cards/add icons, three per-project Settings switches hide the first three, and "Reveal sidebar on hover" lives in Settings > General.
- Selected sidebar rows are semibold on the selected-row fill, `--text` coloured in Plain and section-tinted in Color; the fill slides between rows; Segmented's pressed fill slides too; `docs/design-system.md` and `AGENTS.md` say so.
- Settings > General shows a Section colours row (Color palette only) with three pickers over eight swatches whose light and dark values pass 4.5:1 on every surface (unit test), defaults reproducing today's Color tints exactly.
- The create menu lists Blank, Chicago, Screenplay and saved templates (no Essay, no Story); existing Essay and Story projects still open.
- Backspace in an empty, source-less page footnote removes its marker and its empty note in one step; citation footnotes are untouched (browser test).
- Split view works as specified in K (browser tests prove two-pane editing, one toolbar, focus routing, per-pane undo, persistence of split per project and ratio globally); each pane's edits save.
- The sidebar's Research row lists Bibliography and the sources; the Bibliography page and every export (DOCX, PDF, Markdown, plain text) show the same entries in the same order for each of the three orders and both scopes (unit tests); the choice is saved per project.
- A source can carry one PDF (25 MB cap) stored natively in the project's `assets` table and mirrored to `attachments/<id>.pdf`, or in IndexedDB in the browser; it is listed under the source in the sidebar and opens in the right pane; nothing is fetched from the network (browser tests; native rendering decided by the U17 probe and the owner).
- `README.md`, `docs/architecture.md`, `docs/design-system.md`, `docs/validation.md`, `docs/limitations.md`, `docs/changelog.md` and the later-fixes plan describe the new behaviour; the final validation list passes; every new check was shown failing first; status CLAIMED until the owner confirms real use.

## Approach
One small motion module and one popover component carry the whole wave. `src/motion.ts` wraps `Element.animate` with token durations and easings, refuses keyframes outside transform/opacity/clip-path, short-circuits under reduced motion (no Animation is created, so `document.getAnimations()` is empty and unmounts happen synchronously), and implements reversal by calling `Animation.reverse()` on whatever is running, which continues from the current frame. A `presence` controller and a `usePresence` hook keep an element mounted until its exit finishes; a `slideHighlight` helper moves one 1x1 px fill box with `translate()` + `scale()` so the highlight glides and resizes without animating layout. `Popover` uses all three and replaces every hand-rolled menu surface; Dropdown keeps its keyboard code untouched and only swaps its menu `<div>` for `<Popover role="listbox">`. CSS transitions that remain are tokenised and limited by a Node test over every stylesheet; a Playwright spec samples `document.getAnimations()` during real interactions.

The create menu is the same Popover in `morph="anchor"` mode: positioned over the button, clipped to the button's rectangle at first, the button fading underneath. The toolbar's label mode is a data attribute on the bar plus a second width cache, and the More menu renders overflowed controls as labelled rows. The sidebar keeps its storage: `sidebarOrder` for order plus a new additive sibling `sidebarHidden`, global prefs through one shared helper module. Section colours are swatch tokens plus data attributes on `<html>`, mapped to the existing `--tint-*` tokens only in Color.

Split view keeps App's meaning of `active`: it is always the entry in the focused pane, so every existing feature (insert footnote, comment, extract, research insert) automatically targets the focused pane. A pure `src/split.ts` holds the pane state and its transitions; App renders two Writers, each registering its own editor, and only the focused Writer shows its format bar, portalled into one shared slot above both panes. The bibliography becomes one shared function used by the page and every exporter. Source PDFs reuse the image asset pipeline (`stage_assets`, `read_asset`, the `assets` table, the attachments mirror) with a PDF branch in `inspect`, and render in an `<iframe src="blob:...">` like Preview PDF already does, after a probe.

Rejected alternatives:
- A motion package (Framer Motion, Motion One): owner decision A, and no new packages.
- Keeping CSS `@starting-style` for menus: cannot reverse mid-flight from the current frame on reopen, and WebKit support is unverified (`docs/design-system.md` Motion).
- Hoisting the format bar out of Writer into App for split view: touches all of `Writer.tsx:634-1497`; a portal of the focused Writer's own bar keeps the toolbar code unchanged.
- Encoding hidden sidebar features by removing them from `sidebarOrder`: missing ids are re-appended (`ProjectSidebar.tsx:154-156`), so old projects would behave differently from new ones.
- New Rust commands for PDFs: `stage_assets`/`read_asset` already move verified bytes; a PDF branch in `inspect` is smaller and keeps one asset path.
- `<object>` or `<embed>` for PDFs: blocked by the CSP's `default-src 'self'` fallback (inferred); `<iframe>` is already allowed and used.
- Enforcing PDF presence at commit like images: an archive or old project that lacks the bytes could then never be saved; a missing PDF instead shows "This PDF is not stored in this project." in the pane.
- Making the sidebar title a rename control: native harnesses depend on its navigation click (open question 1).
