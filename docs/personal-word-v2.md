# Personal Word: writing workspace update

## Delivered workflows

- Project library: compact rows, cards, template menu, sorting by name/added/edited with direction control.
- Import writing accepts UTF-8 `.txt` and Markdown (`.md`, `.markdown`) files up to 5 MB, previews the file name, format, excerpt, and warnings, and only creates a new project when Import is chosen; Cancel changes nothing and the source file is untouched. Markdown headings, emphasis, strong, strike, links, nested lists, quotes, and code import into the editable schema; images, tables, relative links, and raw HTML in a plain text or Markdown file are kept as visible literal text with a warning and nothing remote is fetched. Beta board (2026-10-25, CLAIMED): the same import button also takes HTML, Word (.docx) and Markdown-with-images (.zip) bundles up to 20 MiB; these keep headings, lists, links, notes, rectangular tables and PNG/JPEG images, with pre-inflation zip limits, inert HTML parsing, no network access and a Cancel that creates nothing. Full-project JSON recovery remains separate.
- Multiple open project tabs; default startup is Projects. Settings can restore the open tab session.
- Resizable sidebar with global pin/hover preferences, per-project feature order and list/card preferences. Keyboard controls supplement dragging and hovering.
- Fonts, sizes, line spacing, paragraph spacing, paper size, margins, zoom, and explicit page breaks. View changes preserve the mounted editor and undo stack.
- Editable page view uses actual CSS multicolumn fragmentation. Pages are arranged horizontally. Count and current page refer to the open section, not an exported full manuscript. Export pagination is independent.
- Templates: blank, essay, Chicago student paper, screenplay, story, and user-saved structure/settings templates. Blank writing defaults to sans serif. Chicago uses 12 pt serif, double spacing, one-inch margins, half-inch first-line indentation, editable title-page fields, notes, bibliography, and page numbers. Screenplay has named paragraph styles and Tab/Shift-Tab cycling.
- Research: two tabs. Sources holds each work with its Chicago note/bibliography preview, its quotes and paraphrases, and the footnotes that cite it (Cite here, Insert quote + cite); footnotes without a source are listed as text-only notes. Notes holds loose personal notes. Footnote references retain stable IDs and are numbered in manuscript order; clicking a reference opens its source.
- Citation lookup: paste a DOI (Crossref), ISBN (Open Library), or web address (page metadata) and the fields fill in as a draft to review. Nothing is sent until Look up is clicked, and only the typed identifier is sent.
- Writing screen: section title lives in the top bar; one-row formatting toolbar (zoom, style, font, size, marks, link, lists, indent, spacing popover, page view, page setup popover, comment, keep as fragment) that folds trailing groups into a More menu when narrow; page count in the status line. Tab/Shift-Tab indent like Word (lists nest; paragraph start sets a first-line indent; otherwise the paragraph moves 0.5 in). Fragments and Research side panels are resizable (width stored globally). All dropdowns use the flat in-app Dropdown component instead of native selects.
- Chicago 18 citation assistance for common books, journal articles, and websites; full/short notes and a cited-source bibliography. Review complicated names, unusual source types, and institutional instructions manually. Official references are linked in the app.
- Word export produces editable native footnotes; PDF export includes page-bottom notes. **Preview PDF** shows the legacy PDF exporter's own output in the app; it is not an exact print-engine preview (see boundary 2).
- Comments and revision tasks can quote selected text. They remain available and are marked detached when their quoted passage disappears.
- Fragments panel is a split view: each fragment is shown in full and editable beside the main editor (read-only if it is the entry open in the main editor), with Insert at cursor, Append to section, Open in editor, tags, and delete.
- Fragments have tags, search across saved projects, side-by-side browsing, copy with remapped research references, and placement history.
- Snapshot comparison highlights changed paragraphs side by side; restore a section or a paragraph with a safety snapshot first.
- Read manuscript has independent typeface, size, and line-spacing controls and displays note markers and notes.

## Important boundaries

This is an initial implementation of the expanded workspace, not publication-ready word-processing parity.

1. Editor pages, PDF, and Word use different layout engines. Their page breaks and font metrics can differ. The editor shows footnote text below the section in continuous view and at the bottom of the page holding each reference in page view; notes are editable in place. Page view reserves the same footnote space on every page (the tallest page's notes), so pages without notes keep extra bottom space, and very long notes are not split across pages. PDF and Word place notes with their own engines.
2. An exact PDF preview and per-page footnote flow were investigated and stopped (2026-10-25): the native WebKit print probe could not make Arabic with the lam-alef ligature searchable, so the legacy PDF exporter stays the only PDF path (owner question Q004 open). No page parity is promised. PDF draws with bundled Noto Serif, Noto Sans, and Noto Sans Mono subsets instead of the fonts installed on the Mac, so its typeface only approximates the document font. It covers Latin, Latin Extended, Greek, and Cyrillic; other scripts are rejected with a clear message, and Word export is the alternative. Oversized words and URLs are split at Unicode code-point boundaries, which prevents character loss but does not provide typographic hyphenation. A footnote that cannot fit on one page is reported instead of truncated. PDF tables do not repeat the header row on continuation pages, PDF stacks consecutive images with no gap, and Word and PDF omit the project and section titles that Markdown, plain text and the bundle include. A footnote with several paragraphs is written as separate paragraphs in both (task T043, repaired and reviewed 2026-10-25; Word rendering unchecked).
3. Revision comparison is paragraph-based, not a word-level tracked-changes engine. Restoring a passage replaces the paragraph at the same index. The interface states that behavior.
4. Comment anchors use quoted text rather than a full operational-transform anchoring system. Repeated identical passages can be ambiguous; changed or removed quotes are labeled detached.
5. Font families depend on fonts installed on the Mac. No proprietary Futura files are bundled.
6. Cross-project fragment search reads saved projects; it does not index damaged recovery journals.
7. The app is unsigned/not notarized and stores everything locally. Citation lookup is the only internet use and is opt-in per click (the optional Zotero refresh, off by default, talks only to 127.0.0.1:23119 on this Mac); Crossref/Open Library/site metadata can be incomplete or wrong, so results are drafts to review. Web page lookup in the browser preview often fails because sites block cross-origin reads. No cloud sync, collaboration, subscription, or licensing system was added.

## Data compatibility

Project and entry metadata are additive optional fields. Frontend validation shares the editor extensions; native validation recognizes text-format marks, page breaks, and footnote references. Rust structs flatten extra metadata so settings/research/annotations survive the SQLite header/body split, journals, snapshots, and mirrors. The existing database schema is retained.

The historical identifier `com.folio.writing`, localStorage prefixes, event names, and Rust executable/library names remain stable intentionally. These must not be renamed as a cosmetic cleanup. The display name, HTML title, npm package name, documentation, and app icon are Personal Word.

## Writer features -- October 18, 2026

Implementation is CLAIMED pending final qualification and owner real-use confirmation.

- **Zotero:** Research > Sources > Import from Zotero accepts a local CSL JSON export up to 5 MB. Review the preview before Add sources; Cancel changes nothing. Books, journals/magazines/newspapers, and websites/blog posts map to the three source kinds. Duplicate IDs, normalized DOIs, or title/first-author combinations are skipped; unsupported types and malformed records are counted. No import request goes to a server. Beta board update (2026-10-25, CLAIMED): BibTeX files (.bib, .bibtex, 5 MB) import through the same review dialog (a "Jr." suffix stays only in the raw record), and an optional Zotero refresh, off by default, reads Zotero's local API at 127.0.0.1:23119 only, read-only, and every change goes through the review dialog. It has no polling or incremental updates and has not been run against a real Zotero. Live two-way synchronization is not supported.
- **Note forms:** new projects shorten repeat source citations automatically, in manuscript order across sections. Existing projects keep the setting off until enabled in Research. Each note can be Automatic, Always full, or Always short; old shortened flags remain compatible. Reordering a reference recomputes its form. By default the sequence does not restart per section and never uses ibid. An opt-in Research setting ("Use repeat citation rules") can restart full citations in each section -- one manuscript entry, not a guessed multi-entry chapter -- and use roman "Ibid." / "Ibid., 9." for back-to-back plain notes citing one source; ambiguous notes (own text, explicit form, manual or placeholder citation, dropped page) keep full or short forms. Turning the setting off restores the default. A source's Short title wins; otherwise the main title before a colon or question-mark subtitle is used. Longer titles are not reduced to guessed keywords: the writer chooses the short title. Editor, research preview, reading view and exporters share the same resolver.
- **Capture quote:** choose a source and page, then Save to source or Save and insert. Pasting cleans PDF line wrapping and one enclosing quote pair; manual text is preserved. Inline quotes use quotation marks; passages of at least 100 words use a block quotation. Text and reference insert as one editor transaction so one undo removes both.
- **Goals:** Settings offers manuscript/daily word goals and a deadline. Only manuscript sections count. Daily progress uses the total when the project first opens each local date and never goes below zero after deletions. Baselines are local preferences, not cross-device writing history. Compact windows keep the total and hide daily/deadline detail.
- **Writing aids:** Focus mode dims other top-level blocks; Cmd/Ctrl+Shift+F toggles it. Prose check is off until enabled and flags repeated words, possible passive constructions, filler and sentences over 40 words. The keyboard-reachable issue list selects the passage. These are fallible local heuristics, not grammar correction. Quoted passages, block quotations and code blocks are excluded. Decorations do not change the saved document, import schema or exports. A section with an unusually large number of flagged words (roughly two thousand or more, which needs about one flagged word per word) shows only the issues closest to the cursor, and the panel says so.
- **Whole-project text export:** Settings > Export Markdown or Export plain text includes manuscript titles/body, numbered notes, cited bibliography unless disabled, fragments, and research notes. A footnote found only in a fragment appears inline as [Note: ...], preserving manuscript numbering. Since the beta board (2026-10-25, CLAIMED), Markdown import reads these note definitions back, including multi-paragraph notes, with their reference positions and order. A footnote found only in a fragment still appears inline as [Note: ...] in the whole-project export; its import behaviour is not recorded.

Citation assistance is a limited implementation, not certification of a paper's style compliance. The [official Chicago notes and bibliography examples](https://www.chicagomanualofstyle.org/tools_citationguide/citation-guide-1.html) show full and shortened notes. The app's 100-word block-quote default follows [Chicago's quotation guidance](https://www.chicagomanualofstyle.org/qanda/data/faq/topics/Quotations/faq0061.html); context and instructor requirements can override layout. Zotero's [data format documentation](https://www.zotero.org/support/dev/data_formats) describes CSL JSON.
