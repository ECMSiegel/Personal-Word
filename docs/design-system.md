## Type scale

Interface text uses Futura, then Avenir Next, then the system sans-serif stack. Document type is independently configurable.

| Token | Size | Use |
| --- | --- | --- |
| `--type-small` | 12 px | Labels, metadata, compact controls; minimum UI size |
| `--type-body` | 13 px | Root interface text and normal controls |
| `--type-large` | 15 px | Larger controls, including the project switch |
| `--type-title` | 19 px | Brand and panel headings |
| `--type-display` | 28 px | Projects, dialog and empty-editor headings |

Use tokens in both `font-size` and `font` shorthands. Preserve document sizes, line height and letter spacing.
Futura has no tabular figures. Where a number changes in place, request `font-variant-numeric: tabular-nums` anyway (see Separator), but do not promise steady digit widths: the fallback font decides, and Futura's proportional digits keep their own widths. Recorded in [limitations](limitations.md).

## Elevation and sizes

Use `--elevation-page` for the page, `--elevation-surface` for a panel surface, and `--elevation-raised` for menus and other raised controls. `--shadow-raised` supplies the shared raised shadow. Header rows use `--control-height` (32 px) and `--header-gap` (the spacing scale's 8 px gap). Lucide icons use 16 px; chevrons use 14 px. Keep Lucide's default 2 px stroke; do not set `strokeWidth` or `absoluteStrokeWidth`.

An icon button draws a 16 px icon but reaches a 24 x 24 px target: a pseudo-element centred on the button is `max(24px, 100%)` wide and tall, so a 24 px button is untouched and a smaller one still takes a full-size press. Do not grow the padding to fake it; padding moves the row's layout, the pseudo-element does not. The hit-area rule is `:where()`, so it can never outrank a component that positions its own button: the cards-view trash and the Open beside button stay absolutely placed. Only the `::after` box itself uses `:is()`.

## Separator

A separator is one pixel of `--line`. `.separator` draws it: vertical (`role="separator"` with `aria-orientation="vertical"`) stretches to its row and takes no fixed height; the horizontal rule keeps its 17 px length. Never draw a separator as a border on the neighbouring element, because the neighbour then owns its colour and its hover.

The live separators are the toolbar's decorative group dividers (`.toolbar-divider`, 1 px, 16 px tall, 3 px side margins, `aria-hidden`), the create panel's rule (`.create-rule`), and the three draggable splitters: the sidebar width handle, the split-view divider and the side-panel resizer. Each splitter carries `role="separator"`, `aria-orientation="vertical"`, `aria-valuemin`/`aria-valuemax`/`aria-valuenow` and `tabIndex={0}`, so the arrow keys move it. A separator is never the only way to see a boundary: the split divider's hit area is documented under Split view. Since wave 7 none of the three adds anything on hover or drag (see Resize edges).

Numbers that change in place -- the footer's page counter and the save status -- request `font-variant-numeric: tabular-nums`. The rule is applied; whether it is honoured depends on the font (see Type scale).

## Motion

Motion tokens live on `:root` in `src/styles.css`: durations `--duration-press: 80ms`, `--duration-fast: 120ms`, `--duration-base: 180ms`, `--duration-morph: 220ms`; easings `--ease-out: cubic-bezier(0.2, 0, 0, 1)`, `--ease-in: cubic-bezier(0.4, 0, 1, 1)`, `--ease-spring: cubic-bezier(0.34, 1.4, 0.64, 1)`. `--duration-morph` with `--ease-spring` governs the search reveal and create-panel opening.
Stylesheets may transition only `transform`, `opacity`, `clip-path` and `visibility` (never `all`, never layout properties), with a duration token and an easing token (visibility may omit the easing); there are no `@keyframes`. `src/motion.test.ts` enforces this.
The projects search reveals by clip-path: `.library-search` is a fixed 32 px slot (`var(--control-height)`) and `.library-search-field` (220 px, absolutely positioned) is clipped to the magnifier when closed, so it grows leftwards without moving layout.
Scripted motion goes through `src/motion.ts` (Web Animations, no packages): `play`, `presence`/`usePresence` (keeps an element mounted until its exit finishes) and `staggerIn`. Enter uses `--ease-out`, exit `--ease-in`, and `--ease-spring` only for size changes. Keyframes may touch only `transform`, `opacity` and `clip-path` (`checkKeyframes` throws otherwise). Every animation is interruptible: reopening or reclosing reverses the running animation from its current frame instead of starting a new one. Under reduced motion the engine creates no animation at all and exits resolve at once, so unmounts are synchronous (no timers). Nothing runs longer than 220 ms; item stagger is 15 ms per item capped at a 90 ms delay plus 120 ms, and moves `transform` only. `tests/motion.spec.ts` samples `document.getAnimations()` during real interactions to prove the allowed properties and zero animations under reduced motion.
The hover emphasis tokens are `--emph-stroke: 0.04em` and `--emph-scale: 1.04` (see States). The emphasis moves by `transform` only, so the transition rule above still holds; the stroke is not animated. Under reduced motion `--emph-scale` becomes 1: the scale is dropped and the stroke stays.
`slideHighlight` is still exported and unit-tested, but no component calls it: wave 3 removed every sliding highlight box (sidebar, Segmented, Popover). Do not reintroduce it; a selection is shown by weight and colour (see States).
The `prefers-reduced-motion: reduce` block in `src/styles.css` removes all transitions and smooth scrolling. Reduced motion must also apply to new components.
The create menu is a Popover anchored to its button (`morph="anchor"`): it grows out of the button and covers it, the trigger fades while covered, the header does not move, and closing reverses toward the button. Items have no fade-in: they are opaque from the first frame and the clip-path morph alone reveals them, so no menu or panel item may start at reduced opacity (T086). Escape closes from any focus inside the control and returns focus to the trigger. Reduced motion makes the whole morph instant.
Never animate a keyboard action except for one documented exception: a menu or panel that a keyboard opens still grows by its clip-path morph, because the morph is the component's opening, not a decoration of the key press. Nothing else may move or fade because a key was pressed; a value change reached by keyboard changes at once. This is the recorded answer to checklist item R7.

## Popover

Every menu and toolbar panel renders through `src/components/Popover.tsx` (`popover.css`): Dropdown (and so Sort), the toolbar panels (spacing, setup, aids, table, image alt text) and the More menu. Surface `--elevation-raised`, 1 px `--line` border, `--shadow-raised`, square corners. It sits below its anchor, flips up when it fits better above, flips to the anchor's right edge when it would leave the viewport, and caps its height (toolbar panels keep `overflow: visible` so nested menus can spill out). Opening grows it from the anchor edge by `clip-path` with a fade of the surface (`--duration-base`, `--ease-out`); closing runs `--duration-fast` `--ease-in`; a reopen mid-close reverses from the current frame without remounting. While closing it carries `data-state="closing"`, inert and `aria-hidden`, and drops its role and label, so role queries see it gone at once. Items (`[data-popover-item]`) are opaque from the first frame; a fresh opening staggers them by `transform` only (15 ms per item). There is no highlight box: the keyboard-highlighted item is `[data-popover-item][data-highlighted]` and is shown by weight 600 alone, and hovered rows go semibold the same way. `PopoverItem` presses to `scale(0.99)` over `--duration-press`. Shortcut hints (`.popover-shortcut`, from `src/editor/shortcuts.ts`) sit right-aligned in `--muted` at `--type-small` on one line, only where the editor really installs the shortcut, and follow the user's rebinds. Dropdown menus size to their content (max 320 px) except when bounded (next paragraph).

**Placement follows the nearest scrolling ancestor (wave 5, B2).** `placePopover` in `Popover.tsx` is one pure rule. Without a scrolling ancestor it behaves as above (the toolbar and More-menu chain has none, so those popovers did not move). When the popup sits inside an element whose computed `overflow` is `auto` or `scroll` (`nearestScrollBoundary`; `clip`, `hidden` and `visible` do not count), the same flip decisions run against that element's rectangle intersected with the window, and the popup carries `data-bounded`: its width is capped at the boundary width minus 16 px and long labels wrap (`overflow-wrap: anywhere`, `popover.css`) instead of sizing to their content, so the menu cannot leave its container's left or right edge (the research panel's Full citation again menu was clipped by the aside before). The wrapped menu is taller than the natural one, so the height cap is read after the width cap is applied and the last item is never cut. Placement re-runs on window resize and when the boundary scrolls. Covered by `tests/popover-bounds.spec.ts` and `src/components/Popover.test.ts` (Chromium only, CLAIMED).

## Toolbar

The format bar is icons only at every width. The width-based label switch, its threshold constant and its attribute are gone; so are the width cache and the re-measure when crossing a threshold. Icons keep their `aria-label` as the accessible name, for example "Bold (Cmd+B)".

The bar's own gap between groups is 0: groups abut and a 1 px `--line` divider (3 px margins) marks each boundary. Inside a group icons sit 2 px apart. Toolbar icons are 28 px wide at `--control-height`, default to `--muted`, go to `--text` on hover, and to `--accent` when pressed (`aria-pressed="true"`); keyboard focus shows the focus ring, not a colour change. Weight and colour, never a fill (see States).

**Format-bar dropdowns have no box (wave 7, lane B).** The zoom, paragraph style (including the screenplay style dropdown in mono font) and font family dropdowns on the format bar draw no border and no fill (`.writer .format-bar .dropdown-button { border: 0 }` in `src/editor/editor.css`, scoped so dialogs and Settings keep their boxes). This also holds when the More menu carries them. Page setup's Paper size and Page margins sit inside the format bar but keep their 1 px box (`.writer .format-bar .toolbar-popover-body .dropdown-button`). Their wrappers keep fixed widths (74 and 104 px), so the bar does not move and the width table below is unchanged. Hover is the shared text emphasis; keyboard focus keeps the outline from `dropdown.css`. The font-size box with the + and - buttons is not changed. Covered by `tests/editor-toolbar.spec.ts` (computed border 0, transparent background, solid focus outline; More at 460 px; Page setup's 1 px box).

**Toolbar dock.** Toolbar icons do not use the text emphasis; they magnify like a dock (`src/components/dock.ts`, `useDock` called from `src/Writer.tsx`, styles in `src/editor/toolbar-motion.css`). The icon nearest the pointer grows to 1.5 times its size and its neighbours follow a cosine curve out to 84 px away (`DOCK_PEAK`, `DOCK_RADIUS`). The pointer writes `--dock-scale` on each icon and the CSS scales the icon's `svg` by `transform` only (`--duration-fast`), so the bar's layout never moves and the 24 px hit area is untouched. **Dock 24 px (wave 6, T227):** the icon artwork is drawn 24 px and scaled down at rest (the scissor included), so the peak magnification draws at scale 1 and no icon is ever enlarged past its drawn size; the on-screen size at rest is unchanged. Whether icons now look sharp at rest in macOS WebKit is for the owner to judge. Keyboard equivalent: a `:focus-visible` icon peaks at 1.5 and its neighbours step down by index (1.25, then 1.1), and that change is instant (a key press never animates). Reduce Motion: no magnification at all, pointer or keyboard. Touch pointers do nothing. Icons inside popover rows (`[data-popover-item]`, for example the More menu) are text rows and use the text emphasis instead. The curve is the standard dock cosine with the plan's constants; the reference page (bencho.dev) was free to use but its source was not readable, so this is a re-implementation.

## States

Wave 3 removed every grey box. Hover, focus and selection never paint a fill. Wave 4 then replaced the mixed cues with one rule: anything that shows text gets the same emphasis, icon-only controls keep a colour change, toolbar icons get the dock. This rewrites the wave-2 and wave-3 hover, pressed and selected text (checklist item R1).

- Hover: icon buttons go from `--muted` to `--text`. Every control that shows text -- button, `a[href]`, tab, `menuitem`, `option`, `summary`, a `label` that wraps a checkbox or radio (a label around a text or number input is not emphasised: scaling it would grow the input box), `.text-action` -- gets the **text emphasis** described below. Sidebar rows stay flat and transparent. Text fields show the muted border.
- Focus: `--focus-ring: 2px solid var(--accent)` with `--focus-offset: 1px`; text inputs keep their accent bottom-border focus. Every control shows `:focus-visible`: icon buttons take the hover colour as well as the ring, toolbar icons take the ring and the dock's keyboard peak, and text controls take the same emphasis as hover (also on `[data-highlighted]`, the keyboard-highlighted menu row), so a keyboard user never loses the cue a pointer user gets.
- Pressed: every button scales to `0.99` over `--duration-press` (never a fill). A toggle or segmented choice shows its state through `aria-pressed`, which is weight 600 plus `--accent` (or the section tint). A primary button's brightness is 0.88 while pressed. Flat sidebar rows stay transparent and turn accent-coloured. The press scale and the emphasis scale multiply (`scale(calc(var(--emph-s) * var(--press-s)))`), so a pressed, hovered button is about 0.99 times its grown size; menu rows and labels press too.
- Disabled: `--disabled-opacity: 0.35` and the default cursor for buttons, inputs, textareas and dropdown triggers; hover and pressed rules exclude disabled controls.
- Selected: weight 600 plus colour. For the sidebar see Sidebar selection below (wave 7: the section heading is bold in `--text`, rows are never bold). A segmented choice is semibold in `--accent` on the plain surface, with roving `tabindex` (Left/Right/Up/Down step and select, Home/End jump). Checkboxes use the accent.

**Text emphasis (the one hover and focus rule, wave 4).** One block in `src/styles.css` (after `button:focus-visible`, "Text-control emphasis") is the only place that sets a hover or focus cue on a text control. On `:hover`, `:focus-visible` and `[data-highlighted]` it sets `-webkit-text-stroke: var(--emph-stroke) currentColor` and `--emph-s: var(--emph-scale)`; the control's `transform` is `scale(--emph-s * --press-s)` with a `--duration-fast` `--ease-out` transition. The stroke is a faux bold: it thickens the glyphs without changing their advance widths, so the control's layout width and every neighbour stay exactly where they are (the owner chose this "no-shift bold" after a real weight change moved neighbours by 10 to 13 px). The grow is 4 percent by `transform`, so it does not reflow either; left-aligned full-width rows grow from their left edge (`--emph-origin`). While a text control is pressed its transition runs over `--duration-press` (`--emph-duration`, set by the `:active` rule). A checkbox or radio label gets the emphasis from the keyboard when its input is `:focus-visible`. The user's document is never emphasised: links inside `.ProseMirror`, `.writing-surface`, `.manuscript-read` and `.preview-content` are in the exclusion list. Because the stroke is `currentColor`, danger controls stay red. Inputs inside a hovered label are reset to no stroke. Reduce Motion sets `--emph-scale` to 1: no grow, the stroke stays.

**Label-only rows (wave 6, T225).** A row with content on its right (a palette option with its shortcut, a project row with its dates) is `.emph-row`, with its text in `.emph-label`. The row itself is excluded from the transform and stroke, and `.emph-row .emph-label` is folded into the same shared selector lists, so only the label grows (from its left edge) and the shortcut, dates and trash never move. This is part of the one rule, not a second one: `src/hoverEmphasis.test.ts` requires exactly one shared stroke and `--emph-s` rule and rejects any other interactive scale. Palette rows keep equal left and right padding (`--space-2 --space-4`).

Icon-only controls, `.toolbar-icon` (outside popover rows), disabled controls and a short list of named exceptions (in the block's `:not(...)`; `.spy-line` is one) are excluded. A new button, link, tab, menu row or summary gets the emphasis with no new CSS. **Do not add any other rule that sets `font-weight`, a hover scale or a text stroke on hover or focus**: `src/hoverEmphasis.test.ts` fails if one appears, and `tests/hover-emphasis.spec.ts` crawls about twenty screens and fails if a text control shows no stroke or moves a neighbour. The Snapshot button is an ordinary text-and-icon control with no border.

The stroke width (0.04em) was tuned against a true 600 weight in Chromium's fallback font. How it looks in Futura in the Mac app is not yet confirmed (see [limitations](limitations.md)).

The old "doubling rule" (group title stepping back to 500 when an entry is selected) is gone; the section heading is the louder cue (see Sidebar selection).

The fills that remain, and the only ones allowed:

| Where | Fill | Why it is not a hover box |
| --- | --- | --- |
| Primary button | `--accent` in Plain; `--accent-fill` with `--on-accent` text in Color | it is the action's identity, not a state |
| Destructive primary | the same as a primary in Plain; `--danger-fill` in Color | same |
| Active project tab | `--paper` | it is the tab's surface, standing for the open document |
| Selected entry in cards view | `--paper` with a `--muted`-mixed border | a card is a surface; weight alone does not separate it from the cards beside it |

The cards-view selected card is a recorded exception to the no-fill rule, not a precedent: it is a bordered card in a grid, and the border alone reads as hover. Any new fill needs the same justification written down here.

Every hover action needs a keyboard path. Existing component states take precedence where already defined; the shared recipe fills missing states.

## Theme and palette

`src/appearance.ts` owns the global `folio.workspace.appearance` JSON preference: `{ theme: "system" | "light" | "dark", palette: "plain" | "color" }`. Defaults are System and Plain; invalid values fall back per field.
Apply it in `src/main.tsx` before React renders, then in the `src/App.tsx` effect when settings change; persist the same preference there. This does not alter project data or the SQLite schema.
On `<html>`, System removes `data-theme`; Light and Dark set `data-theme="light"` or `data-theme="dark"`. Plain removes `data-palette`; Color sets `data-palette="color"`.
System follows macOS live. Explicit Light overrides the system dark media query. Dark declarations in the media block and `[data-theme="dark"]` block must match, ignoring `color-scheme`; `src/designTokens.test.ts` enforces parity.
Settings > General provides Appearance (System, Light, Dark) and Palette (Plain, Color) segmented rows without helper captions. Cmd/Ctrl+Shift+L switches to the opposite effective Light/Dark appearance.
There is one General block, defined once in `src/settings/GeneralSettings.tsx` and shown in two places: the Settings destination and a Settings dialog opened from the gear at the right of the Projects screen's display row. The dialog reuses the destination's field rules rather than a second layout, so the two cannot drift; it is 560 px wide to hold the 180 px label column and the 260 px control column, hides the block's own heading because the dialog title carries it, and drops the section's top rule and the page padding. The dialog carries the whole block, Shortcuts included, because Shortcuts is part of General; it is not a second, smaller settings screen. Escape or Close returns focus to the gear. Project settings -- Sidebar and Goals -- stay in the destination and never appear in the dialog.
In Color, Section colours provides Manuscript, Fragments and Research swatch pickers. ## Rules

- Keep flat, restrained surfaces and square corners. No decorative folders, quills, curved connectors, slogans or heavy footer strips.
- Sidebar selection is weight and colour, never a fill: the lit section heading is bold in `--text`, rows are dim until hovered, focused or open and never bold (see Sidebar selection).
- Hover and keyboard focus on text controls use the one shared text emphasis; toolbar icons use the dock. No second hover weight, scale or stroke rule (see States).
- Do not add helper captions under controls. Use placeholders, existing error messages, or keyboard-reachable tooltips with `title`, `aria-describedby` and a focus-visible tip. Preserve the browser-only storage notice and the research file error messages.
- Use `--` for UI dash separators. Never rewrite punctuation in documents, citations, code or paths.
- Never alter document typography: `.writing-surface`, `.read-prose`, `.manuscript-read`, `.read-title`, `.preview-content`, editor footnote/page rules and `--prose-*` values stay outside the UI sweep. Reading preferences must not change export formatting.
- Keep hover controls keyboard-accessible, appearance live throughout, sidebar width global and list/card views per project.
- Never animate a keyboard action, except the documented menu-opening morph (see Motion).

## Pages

Page view stacks pages vertically in one ProseMirror flow (`src/editor/pagination.ts`): the plugin measures top-level blocks and inserts a spacer widget before the first block of each new page, or inside a paragraph before the first character of the line that starts the next page, so the editor keeps one DOM, one undo history and normal caret movement. Paragraphs split between lines as in Word's default widow and orphan control: at least two lines stay on each page, so a paragraph of three lines or fewer moves whole; a heading moves with the paragraph after it when that paragraph moves whole. Other blocks (lists, quotes, tables, images, code) that do not fit move whole, and one taller than a whole page starts a page and runs straight across the page gap and margins. That overflow is the documented limit, not a bug. Up and Down across a gap are moved by the plugin, because WebKit's own line movement skips the last line above a gap. A manual page break (Shift-Enter) starts a page. Every page reserves the same footnote space, sized for the page with the most notes. A pane narrower than the page shows the page scaled down (`--page-scale`), never reflowed and never scrolled sideways.

**Ruler and top gap (wave 7, T237).** A toggleable ruler sits above the page, off by default. Its switch is the **Ruler** text button (`aria-pressed`) in the Page setup panel, on the row with Insert page break (the panel is 232 x 136 px from the bar and 204 x 152 px from More; Page setup is itself a More row on narrow windows). It is stored as the additive global preference `folio.workspace.ruler`; in split view both panes show a ruler, each sized and zoomed for its own pane. The ruler is `--paper` coloured, takes its own 24 px, is pinned at the top of the scroller (`position: sticky`; `.is-paged` uses `overflow-x: clip; overflow-y: visible` so `.writer-scroll` is the sticky scroller), swallows pointer events, and clips its own ticks. The page variables (`--page-width` and the rest) are also set on `.editor-viewport` so the ruler's box equals the paper's. Ticks are real elements, not a gradient, and in the native run the ruler's 0 tick, both markers, paper and text edges lined up within about 0.03 px at page 0.75, 1 and 1.15 and continuous 0.75, 1 and 1.5 (Letter, one pane); A4, split panes and a visible scrollbar were not measured. Two keyboard-focusable markers (sliders) are linked: dragging either changes the one real document margin (the one export uses), previewed during the drag and committed once on release; ArrowLeft/Right move 1/16 inch, Shift 1/4 inch, Home/End the limits. Only the main (left) button drags, and pointer capture means a release outside the window ends the drag. A drag is not on the text undo stack (Cmd-Z does not undo it), like the margin dropdown. The marker box is offset by half its width so its point sits on the margin. In continuous view the paper column now has no side padding (it had 8 px), so the first glyph is exactly at the marker (measured in Chromium) and the column is 608 to 624 px wide like page view and exports; some continuous lines rewrap slightly. While the ruler is on, ProseMirror's `scrollMargin` and `scrollThreshold` for the top equal the ruler's measured height plus 5 px (re-measured on zoom, view and fit changes, per pane) so the caret should not sit behind the ruler. `src/caretScroll.ts` (`handleScrollToSelection`, T243) corrects the scroll in WebKit under CSS zoom, where rects are reported in zoomed space; it does nothing at zoom 1 or in Chromium. Measured: in the native harness, moving up by a selection command plus scroll-into-view (not real keys) left the caret line 5 drawn px below the ruler in 20 steps at page zoom 0.75, 1 and 1.15, page 0.75 with the ruler off, and two panes at 0.555; an image node selection ended 5 px clear. Not measured natively: real ArrowUp or ArrowDown, typing, moving down or the bottom edge, A4. Real keys are an owner hand check. Because the caret line sits 5 px clear, a sliver of the line above shows under the ruler (descenders at 75% and up, about half a line at 0.555). With the ruler off, `scrollMargin` and `scrollThreshold` are the defaults (5 and 0).

**Margin range:** the screen cap is 2 inches (192 CSS px), the same as the DOCX, PDF and native-print limit (it was 1.5 inches on screen); the margin dropdown gained 1 1/4, 1 1/2, 1 3/4 and 2 inch presets (unrequested; owner's call). The export panel's own minimum stays 0.5 inch while the ruler allows 0.25.

**Top gap.** Continuous view's top spacing is the additive `pageLayout.topGap` (0 to 200 px, default 32 px for projects that never set it, absent from the saved project until changed). It scrolls away with the top of the document, is screen-only (DOCX and PDF never read it; a unit test asserts the Word `document.xml` is byte-identical for gaps 0, 128 and 200), and a top-gap-only change never rewrites `documentSettings.marginInches` (`App.tsx` syncs only when the real margin changes). Its drag handle exists only while the ruler is on and the view is continuous; its bottom edge is the first line's top; ArrowUp/Down move it (Shift 16 px, Home/End the limits). Page view's top padding is still the real margin, and the 32 px between pages is fixed.

**How pages are drawn (wave 4).** The earlier look came from a `repeating-linear-gradient` on `.editor-paper`. The grey gaps were wrong at zoom in WebKit because WebKit does not apply CSS `zoom` to px stops in a gradient, so the bands were drawn every 1056 screen px at any zoom. The page breaks themselves (the spacers) were always correct. Now `src/Writer.tsx` draws one real `div.page-sheet` per page (`aria-hidden`, `position: absolute`, `top = page * (page height + gap)`, `--paper` background, `pointer-events: none`) as the first children of `.editor-paper`, so the sheets and the gaps scale with the paper's zoom in both engines. Sheets sit outside ProseMirror, so they are not in the document, undo, saves, exports, selection or word counts, and print CSS hides them. A Chromium-only drift at non-round fit zooms (for example 1.1495, up to 4 px by page 13) is fixed in `pagination.ts`: `sameBoundaries` compares spacer heights as a running total so sub-pixel differences cannot pile up unnoticed. Measurement itself is unchanged (not done at zoom 1), so WebKit's numbers did not move.

**Backspace and Delete at a page break.** In page view, Backspace at the start of the paragraph after a manual page break, or Delete at the end of the paragraph before it, removes the break (as in Word) and keeps the caret there; undo restores the break (`deleteAcrossBreak` in `pagination.ts`). Before this, ProseMirror selected the break node, which page view draws as nothing, so the caret seemed to vanish. Continuous view is unchanged (it draws the break). In the checks run (Chromium, three seeds) no caret or empty line was painted in the gap between pages; the earlier "one stale frame after Enter" reading came from the test sampler, not the app. That is Chromium evidence only; the owner's hand check in the Mac app is still open. The footer shows "Section page N of M" for the focused pane.

Page view and the exports use different layout engines: PDF and Word pagination have their own line-splitting rules, so exact page parity is not promised (see [limitations](limitations.md)).

The owner chose Word's behaviour on 2026-10-28 (board question Q018); the line-splitting rule is CLAIMED, not VERIFIED, until the owner has used it. Where a paragraph breaks across pages, the end of one page and the start of the next are the same position in the text: the caret there is drawn at the top of the next page, so a click in the page's bottom margin or an Up move to that line places it one character before the line's end.

## Focus mode

Focus mode hides the sidebar (as before; in split view the sidebar was seen to stay visible, not traced) and, from wave 4, also the formatting bar of a single pane (`src/Writer.tsx`, `src/editor/toolbar-motion.css`). While hidden the bar is an overlay that takes no layout space (`data-focus-hidden`, moved up by `translateY(-100%)`, transparent, not clickable) but stays focusable, so Tab reaches it. It appears when: the pointer comes within 56 px of the top of the writing area, keyboard focus enters the bar, or the rebindable shortcut "Show formatting bar" (`focusToolbar` in `src/shortcuts/registry.ts`, default Cmd+Alt+T) is used. A pointer reveal slides in over `--duration-base`; a keyboard or shortcut reveal is instant (`data-reveal="key"`); Reduce Motion is always instant. It hides again 600 ms after the pointer leaves, unless a toolbar panel is open or focus is inside the bar. Escape in the bar hides it and returns focus to the editor. Space for the bar is reserved at the top of the scroll area (`.writer[data-focus-toolbar] > .writer-scroll` padding of one control height plus two `--space-1`), so turning focus mode on or off, or revealing the bar, never moves the text and a revealed bar does not cover the first line. In page view the reserved band is the grey desk (the paged viewport's own surface), not white. Split view's shared bar is never hidden: in split view it stays visible in focus mode (`hidesBar` in `src/Writer.tsx` is false when the bar is portalled), so neither pane jumps and the bar never covers the pane headers. ## Shortcuts

`src/shortcuts/registry.ts` owns every shortcut the app itself binds: Focus mode, Keep as fragment, Insert page break, Save, Take snapshot, New section, Find in project, Toggle sidebar, Switch light or dark and Command palette (Cmd+Shift+P; wave 5 -- see Floating layout), each with a default chord and a scope. Show formatting bar (Cmd+Alt+T) reveals the formatting bar in focus mode. `src/shortcuts/store.ts` stores only the user's overrides, as `folio.workspace.shortcuts`; corrupt, unknown and read-only entries are dropped on read. `src/shortcuts/chords.ts` parses and formats them, and `resolveChord` treats Ctrl as Command, as the app's handlers always did. Browser and macOS chords (`Cmd+C`, `Cmd+V`, `Cmd+Z` and the rest of `RESERVED`) can never be assigned.

Settings > Shortcuts lists each action with its chord in a quiet `kbd`; Change records the next chord and Escape cancels the recording; a reserved or duplicate chord is refused with an inline status rather than an alert. Reset restores one action, Reset all restores every action. Insert page break is listed read-only because the editor library binds it. Menu hints follow the user's rebinds. Shortcut hints appear only where the editor really installs the shortcut -- a hint that is not installed is worse than no hint.

Shift-Enter inserts a manual page break; Cmd-Enter is the soft line break. Inside a table cell Shift-Enter stays a soft break, because a page break has no meaning inside a cell.

## Optical alignment

An icon whose ink does not sit in the centre of its box is nudged with `--optical-x` and `--optical-y` on the button, applied as a `translate()` on the `svg`; never pad the button, because padding changes the row's layout and the hit area.

Measure by ink, not by box: rasterise the icon, take the bounding box of the drawn pixels, and compare its centre with the button's centre. Nudge only when the offset is at least 1 px, and round to the nearest half pixel. Re-measure when an icon changes or a control's size changes.

| Control | `--optical-x` | `--optical-y` | Why |
| --- | --- | --- | --- |
| Toolbar icons (18 measured) | none (0) | none (0) | largest ink offset 0.33 px (Bold, Numbered list), under the 1 px threshold |
| Sidebar icon buttons | none (0) | none (0) | verified by the 24 x 24 hit-area test, not by ink measurement |
| Menu and dropdown items | none (0) | none (0) | text rows, no icon centring question |

The hook stays available and costs nothing when unset. The honest coverage limit: the measurement script saw the toolbar's 18 icons, while the sidebar icon arrays came back empty on the page it visited, so the sidebar rows are verified by the hit-area test alone.

## Drop targets

A drop target is the region that will take a file, wrapped in `src/components/DropTarget.tsx`. While a file drag is over the window the region draws a 1 px inset outline -- `--accent` when it can take the item, `--danger` when it cannot -- and one line of label in the same colour; refused items show the reason as that label. Nothing else on the page changes: no backdrop, no dimming, no moving layout. The outline and label disappear the moment the drag leaves or ends.

The keyboard path is a real button, not a hidden input: it opens the system picker and the chosen file goes through exactly the same acceptance check as a dropped one, with the same refusal message. Its label and accessible name are the target's own ("Import writing" on the Projects screen, the source's PDF slot in Research), never a bare "Select files". It is a text button at `--control-height` with the icon-button recipe's colour behaviour, placed where the region's other actions live.

In the browser the target receives `File` objects; in the Mac app drops arrive as paths and are read with `readDroppedPath`, and a drop only counts when it lands inside the region. The Projects screen accepts the importer's types (`.txt`, `.md`, `.markdown`, `.docx`, `.html`, `.htm`, `.zip`) and not `.json`; a `project.json` comes back through Recover, not by dropping it. A PDF dropped on a source's PDF slot in the Mac app is read by its own command (`read_dropped_pdf`) under the same guards -- the path must come from the latest drop, be a regular file and not a symlink, have a `.pdf` extension, and be 25 MB or smaller -- so the importer's allow-list does not grow and its refusal test stays true; the slot then calls the same attach path as the picker. Native Finder drops and PDF drops into the PDF slot were not run tonight, so both are owner hand-checks: this section records the code's guards, not a tested native drop.

**Setting.** Settings > Sidebar (wave 6; it was under General) has a checkbox "Floating sidebar and research", directly under "Reveal sidebar on hover" (`GeneralSettings.tsx`, in the Settings destination and in the Projects-screen dialog, since that block is defined once). It is stored as the additive boolean `floating` in `folio.workspace.sidebar` (`src/sidebarPreferences.ts`): missing or non-boolean reads as false, so it is off by default, and `writeSidebarPreferences` merges into what is stored so the sidebar's own `{ width, pinned }` writes never erase it. It is global, like the rest of that key.

**The one rule: never overlap document text.** Floating mode uses a side only when that side's page margin is wide enough, and otherwise the normal panel shows. `marginFit(side, marginPx, wanted)` in `src/components/floating.ts` returns `width = min(max, wanted, margin - 2 * FLOAT_GAP)` and `fits = width >= min`. Constants: `FLOAT_GAP` 16 px (the gap to the window edge and to the page), `SIDEBAR_MIN` 190 px (the sidebar's own minimum), `CARD_MIN` 280 px and `CARD_MAX` 360 px for the citation card. So the left (sidebar) side fits from a margin of 222 px (190 + 2 x 16) and is as wide as the margin allows up to the user's saved width; the right (card) side needs a margin of 312 px (280 + 2 x 16) and is never wider than 360. App passes the sidebar's maximum (520) as `wanted`, and `ProjectSidebar.tsx` draws `min(prefs.width, floatFit.width)`, so the user's chosen width is respected and only shrinks when the margin is tight. The measure is the room inside `<main class="workspace">` (not `.app`: a pinned research panel would inflate the margin, flip the fit, and nothing would resize), so a research panel that takes room from the workspace takes it from the fit too.

**Where the edges are measured** (`documentEdges`): the document column is `.editor-paper` in page view, `.writing-surface` in continuous view and `.manuscript-read .read-prose` in Read. Left and right margins are that element's rect against the workspace's rect. The vertical extent runs from the bottom of `.format-bar` to the top of `.pane-footer` (or the window bottom); in focus mode, where the bar is hidden, the top is the writing area's top plus the reveal band `calc(var(--control-height) + 2 * var(--space-1))` (`FOCUS_REVEAL_BAND`), so nothing floats under the band that reveals the bar. There is no fit (the normal panels show) in split view, on a destination page (Settings, Comments, Bibliography) and on Versions/History, which cover the document (`documentOnScreen`).

**Re-measuring.** A `ResizeObserver` on the workspace and the document element plus the window `resize` event, throttled to one animation frame. None of the following changes the size of anything observed, so App folds them into `FloatContext.key` (`project id | destination | active entry | page zoom | focus mode`), which is an effect dependency and forces a re-measure: opening a project from the Projects screen, switching destination or entry, changing page zoom (CSS zoom) and toggling focus mode. Inferred, not measured here: a 816 px sheet in a 1440 px window leaves about 312 px each side, right at the card's limit, so page view above roughly 100 % zoom falls back to the panel (see limitations).

**The floating sidebar has no background.** `.sidebar-shell.is-floating` (`floating.css`) is bare text on the page's own background: no fill, no border, no shadow on the sidebar, the search field, the title row or the group action buttons. The shell is absolutely positioned from the window edge, so the hover-reveal strip stays at x = 0, and takes no flex space, so the workspace spans the full width; since wave 7 (lane C) the sidebar box starts at the shell's left edge (`left: 0`), so its own `--space-3` padding puts the search icon, headings and rows at the same x as the docked sidebar (it was 16 px further right), and the hover-reveal strip (`.sidebar-edge`) is 8 px like the docked one; the box sits between the measured top and bottom (`--float-top`, `--float-bottom`, converted from viewport px to `.app`'s box in a layout effect; `.app` is `position: relative`). z-index 4, below the format bar and every popover. Hover and focus use the one shared emphasis rule from `styles.css`; `floating.css` adds no stroke or scale rule. Unpinned, it is hidden by `opacity` plus a `--space-2` slide (tokens only), instant under Reduce Motion, and `inert` while hidden; revealing leaves `visibility` out of the transition so Show sidebar by keyboard can focus the pin at once. Contrast of the tints on `--paper` (measured in `ui5-c3/contrast.md`): nothing below 4.5:1; the lowest is Plain light `--muted` at 5.20 on paper and 4.78 on the grey `--surface`; all eight Color swatches in light and dark are 5.66 or more on paper. In floating mode only, the wave-4 1 px `--line` separators above Read, Comments, Snapshots & history and Settings are removed (`border-top: 0` on `.sidebar-bottom-groups .sidebar-group + .sidebar-group` under `.is-floating`; the docked sidebar keeps them) -- the owner's choice, since a hairline floating over the page read as a stray rule (E4). The list hugs its content (`.sidebar-groups { flex: 0 1 auto }`), so there is no tall empty box, and the resize handle paints nothing in floating mode either (wave 7, T236). On a short window the floating sidebar's group list is its own scroll region that ends above the bottom rows and fades at its edges with the scroll fade below, floating only (the docked sidebar has no fade).

**The citation card is the one floating thing with a surface.** `CitationCard.tsx` / `citation-card.css`: `--elevation-raised` background, 1 px `--line`, `--shadow-raised`, square corners. A surface is needed because, unlike the sidebar's list, it holds inputs, a Dropdown and a preview that must stay readable and show their edges beside document text; it is a raised dialog, not a panel. It is rendered inside `<main class="workspace">` by `App.tsx`, absolutely positioned at `right: FLOAT_GAP`, `top` at the measured top, `width` the right fit (280 to 360 px), `max-height` the room down to `.pane-footer` less `FLOAT_GAP` (`--card-max-height`, set in a layout effect; the body scrolls inside it and the footer link stays visible). Its `z-index` is 39: the format bar, toolbar popovers and `.popover` are all 40, so "above the format bar and below every Popover" is not satisfiable; 39 keeps every menu (including the Dropdown list opened inside the card) above it, and the card never overlaps the bar, the top bar, the sheet or the footer because its box is the margin. It is a non-modal `role="dialog"` whose name follows its heading ("Add a citation", or "Edit citation" while showing the footnote it was opened for); a polite `role="status"` line announces progress; a pointer open fades and slides in (`opacity` and `transform` tokens), a keyboard open never animates, and Reduce Motion is always instant.

**When the card shows.** `showCard = floating && right margin fits && !split && !fullResearch && destination === "research"`. Behaviour: the Research heading opens it in the "new" stage (look up a DOI, ISBN or web address, or Enter manually); Look up or Enter manually leads to "preview" (the compact source form, Note and Bibliography previews, **Cite here**, Start over); Cite here inserts the footnote at the caret and moves to "cited" (Page, Note form, a Preview, Add another, Done). Clicking a footnote number in the text opens the card straight on that footnote in "cited" (switching footnote when the card is already up). Escape closes it (but first closes an open Dropdown), as do the X button and Done; focus returns to the element focused when it opened, or to the editor. "Open full research panel" in its foot, a source or note row in the sidebar and the Research "+" (add note) go to the ordinary panel, as does everything when the card does not fit. Citation logic is shared with the panel (see architecture.md); a card citation and a panel citation produce identical footnotes (spec-checked). After **Cite here**, focus goes to the card's own Page field (wave 7; it was the new footnote's text field in the page). Tiptap's insert refocuses the editor on the next frame, so the card takes focus back one animation frame later (`CitationCard.tsx`). Tab from there reaches the rest of the card.

**Fallbacks.** Margin too narrow: the normal sidebar (docked or overlay) and the normal right-hand research panel, with no visible difference from floating off. Narrowing the window while the card is open hands over to the panel at once. Split view: always the normal panels, both sides. Destination pages and Versions: always the normal panels. No hysteresis (wave 6, T229): the fit is `jointFit` in `floating.ts`, which lays out each end state (both floating, sidebar only, card only, neither) from state-free inputs (row width, pinned sidebar room, research aside room, and how the column follows the workspace in page and continuous view, zoom included) and picks the most floating state that fits, so the result depends only on window, zoom, view and destination and cannot flip back and forth. Widening the window hands the Research panel back to the card. The notice toast (bottom right) moves left of the card or the research panel while one is on screen (`right: calc(<clear> + var(--space-4))`).

**Command palette, not part of the floating layout.** `CommandPalette.tsx` / `command-palette.css` (E3): a non-modal `role="dialog"` named "Command palette", `position: fixed`, 12vh from the top, centred, `min(560px, 100vw - 2 x --space-5)` wide and at most `min(420px, 70vh)` tall, `z-index` 60, with the citation card's raised surface (`--elevation-raised`, 1 px `--line`, `--shadow-raised`, square). Inside: a `role="combobox"` search field (`aria-controls` the list, `aria-activedescendant` the active option) over a grouped `role="listbox"`; rows reuse the dropdown row look with the chord hint at the right, and the active row is colour plus the shared emphasis, never a fill. Filtering is a case-insensitive substring on label and group. Up and Down move the active row (wrapping), Enter runs it and closes, Escape closes, Tab stays in the field; focus returns to the element that was focused at open. A pointer open fades and slides in; a keyboard open and Reduce Motion are instant. The shortcut `commandPalette` (Command palette, default Cmd+Shift+P, app scope, rebindable in Settings > Shortcuts) is in `src/shortcuts/registry.ts`. Cmd+Shift+P opens it (`runAppAction('commandPalette')` in `App.tsx`; mounted once, after the citation card) when a project is open and no modal dialog is up, and the same chord closes it. Commands: every app-scope action except the palette itself, each with its current chord (`hintFor`, so a rebind in Settings > Shortcuts changes the hint), then New fragment, Go to every section and fragment, and Go to Research, Comments, Bibliography (only when it is shown), Snapshots & history, Settings and Read (a destination switched off in Settings > Sidebar is skipped; Settings never is). Editor-scope actions are not listed. It closes on Escape, on Enter, on a press outside it, and whenever a modal dialog opens (palette z-index 60, modals 70: it is closed rather than shown under one). Focus goes back to where it was, and if that was the editor the caret is put back exactly (the selection range is saved at open, because focusing the field drops it). A pointer open fades in; a keyboard open is instant. Shape and behaviour were read from the BoardUI catalogue (MIT) for ideas only; no code, Tailwind or React Aria was copied or installed.

### Scroll fade (wave 5, E2)

A scrolling region that has more content beyond an edge fades that edge with a mask, never a surface or fill. `watchScrollFade` / `useScrollFade` (`src/components/scrollFade.ts`) set `data-scroll-top` when `scrollTop` is more than 1 px and `data-scroll-bottom` when more than 1 px of content lies below (scroll event throttled to one animation frame, plus a `ResizeObserver` and a `MutationObserver` for content that grows without resizing the region; attributes are removed on cleanup). `scroll-fade.css` turns them into a `mask-image` linear gradient `var(--space-4)` (16 px) deep at the top, the bottom or both edges. There is no transition (a mask cannot be transitioned with tokens) and Reduce Motion changes nothing. Used on the Research panel's scroll container, the citation card body (its footer -- Cite here, Start over, Open full research panel -- sits outside the scrolling body with a top rule, so it stays visible) and, in floating mode only, the sidebar's group list. Exemption: no fade while a menu or dialog is open inside the region -- the rule is `:not(:has(.popover, .modal-backdrop))`, because a Dropdown is a `.popover` drawn inside the region and would be faded at the edge, and a modal inside a masked ancestor loses its fixed positioning and hit testing (the capture-quote dialog failed until exempted). The mask therefore snaps off and on as a menu opens and closes. Needs `:has` (WebKit 15.4 or later). Chromium only, CLAIMED; `src/components/scrollFade.test.ts` covers the pure edge function and `tests/scroll-fade.spec.ts` the masks.

### Sidebar right-click menu (wave 5, E4)

`src/components/ContextMenu.tsx` / `context-menu.css`: a `role="menu"` of `menuitem` rows (the `dropdown.css` row look, active row by `data-highlighted` so the shared emphasis rule applies, no fill, square, raised surface). It opens on right-click (`contextmenu`, default prevented) and on Shift+F10 or the ContextMenu key on a focused `.entry-main` or a collapsible group heading. It sits at the pointer (keyboard: below the row), is placed inside the sidebar from viewport coordinates, and flips or clamps 8 px inside the window. Up, Down, Home and End move over the enabled items, Enter or Space runs one, Escape closes and returns focus to the row (without hiding an unpinned sidebar); Tab, a press outside, a resize or a scroll closes it. A pointer open fades with `--duration-fast`; a keyboard open and Reduce Motion are instant. Items: section or fragment -- Open, Open beside, Rename, Move up, Move down, Delete (danger colour; App's existing confirm and safety snapshot, the one new prop `onDelete`); source or note -- Open, Move up, Move down; a PDF row -- Open, Open beside, Move up, Move down (the move acts on its source); Bibliography -- Open; a group heading -- Collapse or Expand, Move up, Move down. The Move items use the same functions and announcement as Option+Up/Down and are disabled at the ends. The bottom rows (Read, Comments, History, Settings) and the editor get no menu. Covered by `tests/sidebar-context-menu.spec.ts` (Chromium only).

## Section colours and templates

In Color, Settings > General shows the Section colours row (Manuscript, Fragments, Research swatch pickers); the row is hidden in Plain. ## Bibliography and PDFs

Research in the sidebar lists Bibliography when it applies, then every source (lead author -- title (year)) with the source's PDF listed under it, then the project's research notes (`src/App.tsx:1931-1943`). Clicking a note opens the Research panel's Notes tab, which groups notes attached to a source separately from loose notes. Bibliography is conditional (`showBibliography` in `src/App.tsx`): the row appears for a project started from the Chicago template, or once the project has a source or a footnote that cites one, and otherwise the destination falls back to the manuscript. The Bibliography page (`src/research/BibliographyPage.tsx`) is read-only: an order menu (Alphabetical by author, Order first cited, By source type) and an Include uncited sources checkbox, saved per project as `bibliographyOrder` and `bibliographyScope` in the document settings (`src/research/types.ts`) and used by every export (`src/research/bibliography.ts`); entries have a hanging indent and type headings are semibold. Clicking a source opens the Research panel with that source expanded. Read manuscript ends with the same Bibliography after Notes. A source may carry one PDF (25 MB cap, `src/assets/pdf.ts`); it is drawn in a right-pane iframe (`src/research/PdfPane.tsx`) from a local blob URL that is revoked on unmount, and it is never fetched from the network. A missing PDF shows an alert instead.
